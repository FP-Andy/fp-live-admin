# FinePlay Highlight (로컬 앱)

경기 영상에서 하이라이트를 만드는 데스크톱 앱. **하이라이트 제작만** 각자 PC에서 한다.

## 왜 만들었나

클립을 합치고 점수판을 새기는 일은 재인코딩이라 CPU를 오래 문다. 그걸 여럿이 동시에
서버에 시키면 서버가 죽는다(실제로 한 번 죽었다). 그래서 무거운 일만 각자 PC로 내리고,
서버는 FLA 로그를 파일로 내주는 창구만 한다.

FLA 운영(경기 태깅) 자체는 **서버 그대로**다. 중계 오버레이·앱 연동·여럿이 한 경기를
나눠 보는 것이 실시간이라 로컬로 내리면 끊긴다. 서버가 죽은 원인은 FLA가 아니라 제작이었다.

## 쓰는 순서

1. **서버(FLA 경기 화면)** → `하이라이트 로그 저장` → `.json` 파일을 받는다
   (골·유효슛·슛·HL 버튼·하프타임 경계·팀명이 한 파일에 들어 있다)
2. **앱** → 풀영상 열기 → `로그 파일 열기` 로 그 `.json`
3. 영상에서 **전반 시작·후반 시작** 지점을 찍는다 (경기 시계 ↔ 영상 시간을 잇는 앵커)
4. `로그 가져오기` → 태그가 자동으로 찍힌다. 손으로 더 찍어도 된다
5. `클립 N개 추출` → `하이라이트 만들기`
6. 완성본은 `폴더에서 열기` 로

## 화면은 콘솔과 같은 코드다

UI를 새로 짜지 않고 콘솔의 '수동 태깅' 화면을 그대로 담는다(Next 를 앱 안에서 띄운다).
두 벌로 만들면 반드시 어긋나기 때문이다. 앱 안에서는 `window.fhlLocal` 다리가 놓여 있어
서버로 가던 길(로그인·잡 만들기·클립 올리기·합치기)이 그쪽으로 돌아간다.

## 서버와 결과가 같은가

같다. `merge.js` 는 서버 `highlight_jobs.merge_manual_clips_for_job` 을 옮긴 것이고,
**같은 입력에 같은 ffmpeg 명령을 한 글자까지 똑같이** 낸다(네 가지 경우로 대조 확인).
저쪽에는 어렵게 알아낸 것들이 박혀 있으니(조각으로 나눠 굽기·출력 픽셀포맷 못 박기·
acrossfade 대신 afade 합성·점수판 마지막 구간 lt/gte) 새로 짜지 말고 같이 고칠 것.

점수판 그림은 서버처럼 따로 그리지 않고 **화면의 미리보기를 그대로 PNG로 뜬다.**
사람이 보고 고른 그 판이 그대로 영상에 박힌다.

## 빌드

```bash
cd apps/desktop
npm install
./prepare-web.sh     # 화면(Next standalone)을 굽는다 — 포장 전에 한 번
npm run dist:mac     # → dist/FinePlay Highlight-<버전>-arm64.dmg  (약 150MB)
npm run dist:win     # 윈도우용 (윈도우 PC 또는 CI 에서)
```

## 받는 사람에게

맥에서 처음 열 때 **"확인되지 않은 개발자"** 경고가 뜬다. 서명을 안 했기 때문이다.
`응용 프로그램` 에 넣고 **우클릭 → 열기** 를 한 번 하면 그다음부터는 그냥 열린다.

경고를 아예 없애려면 Apple Developer 계정의 `Developer ID Application` 인증서로
서명·공증하면 된다(계정은 이미 있다 — FinePlay iOS). `package.json` 의
`build.mac.identity` 를 `null` 에서 인증서 이름으로 바꾸고 `notarize` 를 켜면 된다.

## 만들어지는 자리

- 완성본: `~/Library/Application Support/FinePlay Highlight/jobs/<시각>/하이라이트_<시각>.mp4`
- 중간 클립·조각은 합치기가 끝나면 지운다. 완성본만 남는다.
