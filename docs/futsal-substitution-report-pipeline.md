# 교체 타임로그와 리포트 자동 연결

## 교체 후보 판정 v6 (2026-10-13)

- 모델과 원본 검출 결과를 유지한다. 터치라인에서 안정적으로 대기한 뒤 코트 안으로 지속 이동하는 경로를 `경계 대기 후 입장` 후보로 표시한다. 최근 코트 안 활동이 있는 재진입은 이 보완 규칙에서 제외한다.
- 재탐지 ID를 경유한 결합도 연결된 모든 원본 트랙을 검사한다. 같은 시각 서로 다른 위치에 존재하는 원본 선수를 하나의 경로로 합치지 않는다.
- 기존 12초 후보가 부족할 때 최대 24초까지 검색하되, 더 가까운 같은 팀 교체 로그를 넘어 가져오지 않는다. 팀 색상 충돌 후보도 숨기지 않고 표시한다. 확장 시간·경계 대기·팀 충돌로 추가된 근거는 직접 확인 전 자동 분리에 사용하지 않는다.
- 원본/재탐지가 지속적으로 같은 몸을 관측한 후보는 중복 표시하지 않는다. 이미 저장한 수동 선택은 유지한다.
- 교체 메모가 `[보류]`로 시작하면 웹에서 보류로 표시하고 분리·PDF 완료를 차단한다. 영상 기록에서 보류 문구를 지우면 다시 검수할 수 있다. 특정 경기명·트랙 번호에 대한 코드 예외는 없다.
- v6 적용은 기존 스냅샷을 수정하지 않으며 리포트를 열거나 새로고침할 때 같은 원본과 최신 로그로 다시 계산한다.

웹과 API를 함께 배포하는 기능이다. DB 마이그레이션, GPU 재분석 및 원본 스냅샷 갱신은 필요하지 않다.

## 사용 흐름

1. 영상 기록에서 팀별 교체 시각 저장.
2. `교체 반영 리포트 열기`로 같은 경기의 최신 스냅샷을 연다.
3. 리포트는 서버 교체로그를 읽고 Web Worker에서 기존 추적 결과를 대조한다. 열려 있는 리포트는 BroadcastChannel/포커스/15초 확인으로 갱신하며, 닫혀 있으면 다음에 열 때 계산한다. GPU 재분석은 하지 않는다.
4. 교체 경계와 기존 신원이 일치하는 항목은 자동 분리한다. 불확실한 항목은 입장·퇴장 객체와 퇴장 분석번호를 영상에서 확인한다. 결정은 기존 서버 교체로그의 `tracking` 필드에 저장된다.
5. 모든 연결이 확인되면 개인 출전 구간별 히트맵/이야기 및 교체 선수 배정표를 포함한 PDF를 추출한다. 선수 5명 고정을 없앴으며 교체 선수도 기본 선택된다.

## 원본 및 갱신

- 최초 분석 스냅샷은 수정하지 않는다. 매번 원본에서 파생하므로 로그 삭제도 이전 결과에 중첩되지 않는다.
- 수동 연결은 스냅샷 ID에 귀속된다. 시각·팀 수정은 연결을 지우고, 스냅샷 변경은 연결을 재검토한다.
- 출전 범위가 바뀐 선수는 이전 문구를 새 구간에 재사용하지 않는다. 갱신 전 작성 문구가 있다면 브라우저 작업 목록에 별도 백업한다.
- PDF 생성 전후에 서버 로그 버전과 최신 스냅샷을 확인한다. 불확실/오류/오래된 결과는 추출되지 않는다.
- 교체 장면 사진은 인증된 `report-frame?time=`에서 서버 FFmpeg로 한 장씩 추출한다. 브라우저의 HEVC 지원 여부와 무관하며 동시 2장/35초 제한과 32장 캐시를 둔다. 일반 재생은 기존 S3 직접 경로를 유지한다.

## 판정 범위

촬영 화면 하단 경계를 기준으로 유니폼·기존 번호·출입 방향·시간을 함께 본다. 같은 객체가 밖에 나갔다 돌아오는 킥인은 교체로 연결하지 않는다. 새로운 분석번호는 별도 출전 구간이며 실제 등번호나 재입장 동일인 확정을 뜻하지 않는다.

들어온 선수의 이후 트랙이 단절된 경우에는 그 이후를 채워 넣지 않고 FPA 검수를 요청한다. 교체 시각만으로 모든 경기의 신원이 복원되는 것은 아니다. 골키퍼처럼 원본 필드 히트맵에 없는 신원도 자동 확정하지 않는다.

로컬 UI는 `/preview`에서 테스트 세션을 부여하고 저장은 메모리에만 반영한다. 실제 API 배포에서는 기존 FPC 세션과 소유권 검사를 사용한다. PDF 생성은 사용자가 팀 리포트 PDF 버튼을 누를 때 실행하며, 타임로그를 저장할 때마다 파일을 자동 다운로드하지 않는다.

## 교체 구간 재탐지 실험 (2026-10-12, 로컬 전용)

기존 전체 분석을 바꾸지 않고 `substitution-report/v3`의 선택적 다섯 번째 인자로 재탐지 sidecar를 대조한다. 운영 웹/API 자동 실행·배포에는 아직 연결하지 않았다. 새로 생긴 검출 ID를 기존 분석번호로 간주하지 않는다.

- `scripts/plan-futsal-substitution-redetection.mjs`는 미해결 로그의 전 16초/후 24초만 계획하고 가까운 구간을 최대 80초로 묶는다. 완료된 로그는 재탐지 대상에서 제외한다.
- `scripts/fpa_cv_substitution_redetect.py`는 기존 YOLO26s, ByteTrack·팀 색상 제약을 유지한 채 하단 교체선의 겹치는 두 영역을 확대 검출한다. 타일 경계 중복 상자를 제거하며 새 결과는 별도 ID 공간과 별도 JSON에 저장한다. CUDA/MPS/CPU와 기존 S3 Range reader를 지원한다. 모델이나 의존성 자동 설치는 하지 않는다.
- `scripts/evaluate-futsal-substitution-redetection.mjs`는 원본 결과와 재탐지 결과를 비교한다. 동일 시각 여러 프레임의 상자 겹침, 팀 충돌과 다중 후보를 검증한다. 기존 관측이 있는 시각은 원본을 우선하고 새 관측으로 단절 구간을 보완한다. 복원된 트랙의 경계 접근은 느린 진입도 고려하되, 실제 관측된 안쪽 이동이 필요하다.
- Sidecar는 dataset ID·snapshot ID·교체로그 revision·영상 이름/길이에 묶인다. 다른 원본, 오래된 로그, 구간 밖 프레임, 기존 ID 충돌은 거절한다. 새 sidecar를 리포트에 적용할 때 이전 편집을 백업하고 장면 캐시를 무효화한다.
- `scripts/plan-futsal-substitution-redetection-batch.mjs`는 경기별 실험 목록만 만든다. 실행 전에 최신 원본과 교체로그를 다시 확인해야 한다. 원본 S3 스냅샷, 운영 리포트, 선수 번호를 일괄 덮어쓰는 기능은 없다.

실행 예시:

```sh
node scripts/plan-futsal-substitution-redetection.mjs source-bundle.json.gz plan.json
python scripts/fpa_cv_substitution_redetect.py --plan plan.json --video source.mp4 --model runtime/fpa-cv/yolo26s.pt --device auto --output recovery.json
node scripts/evaluate-futsal-substitution-redetection.mjs source-bundle.json.gz recovery.json comparison.json
```

원본에서 시각을 보존해 잘라낸 실험 영상은 `--source-offset`을 반드시 지정한다. 특정 구간만 비교하려면 `--window-ids`를 사용한다. 결과 파일이 이미 있으면 덮어쓰지 않는다. `eligible`은 기존 자동 분리를 잃지 않으면서 자동 건수가 증가했는지에 대한 계산상의 조건이며, 사람 검증으로 측정한 정확도가 아니다.

실제 예비 비교: 용인–포항 40초(단일 교체)와 부천–충남아산 약 43초(동시 교체)를 로컬 MPS에서 재탐지했다. 전송용 사본은 원본 비율을 유지한 폭 2560px H.264/15fps이며 순수 추론은 각각 약 70초/76초였다. 원본 해상도 직접 S3 추론 및 CUDA와 동일 성능이라는 뜻은 아니다. 용인–포항의 누락 입장 후보를 복원했으나 기존 활동 번호와 충돌했고, 부천–충남아산도 후보 충돌이 남아 두 경기의 자동 분리 건수는 증가하지 않았다. 이 후보를 확정 결과로 채택하지 않았다. 다음 검증 항목은 교체 경계 전후의 시간 범위를 제한한 번호 귀속과 동시 교체 중복 후보 병합이다.

## 웹 재탐지 후보 검수 (2026-10-12)

`FCM → 매치리포트 → 선수 배정·교체 설정 → 교체 자동 반영`에서 기존 추적과 재탐지 후보를 나란히 보여준다. 후보 사진을 눌러 OUT/IN을 선택하고 퇴장 분석번호를 지정한 뒤 `이 연결 확인 · 리포트 갱신`을 누른다. `장면 크게 보기`는 원본 영상 시각의 사진에 해당 상자를 표시한다. 영상 기록의 리포트 링크는 이 설정을 바로 펼친다.

- `POST /api/futsal/analysis-snapshots/{id}/redetection`: 검증된 sidecar를 별도 S3 객체와 소유권 있는 DB manifest로 등록. 같은 ID의 다른 내용은 거절한다. 자동 GPU 실행은 이 경로의 기능이 아니다.
- `GET .../redetection?metadata=true`: 작은 상태 응답만 확인. Worker가 선택된 버전의 JSON을 한 번 읽는다. 현재 로그와 snapshot/dataset/video가 다른 결과는 적용하지 않는다.
- 후보 등록은 출입 확정이 아니다. 운영 등록 결과는 `reviewOnly`로 보관하며 재탐지에서만 나온 후보를 자동 확정하지 않는다. 기존 출입 근거가 재탐지 색상 때문에 사라지지 않도록 원본 후보도 보존한다.
- `tracking.redetectionId`를 확인 결과와 함께 저장한다. `logContext`는 영상 및 교체 ID·팀·시각만 포함하므로 확인·메모 수정으로 revision이 증가해도 후보가 유지된다. 교체 시각·팀·목록 변경은 재탐지 연결을 무효화한다. 새 결과가 등록돼도 이미 확인한 버전을 임의로 바꾸지 않는다.
- 수동 확인은 입장 이후 그 경로의 관측만 옮긴다. 원본 스냅샷이나 다른 시간의 같은 번호를 통째로 변경하지 않는다. 연결 확인과 이후 추적량은 별도 상태이며, 이후 경로가 끊기면 `연결 확인됨 · 이후 추적 확인 필요`로 남고 PDF 추출을 허용하지 않는다.
- 용인–포항, 부천–충남아산의 기존 실험 결과만 등록한다. 나머지 경기의 재탐지 실행이나 사람의 연결 확정을 대신 수행하지 않는다.

검증: 기존 교체/보존 회귀, 재탐지 원본·구간 검증, 서버 비공개 저장·버전 고정·잘못된 객체 차단, 실제 용인–포항 데이터의 로컬 사진 표시/선택/확정/새로고침 보존. 브라우저 테스트의 선택은 격리된 메모리에만 저장하며 실제 교체 판단으로 채택하지 않는다.

## 출입 검수 개선 (2026-10-13)

- 리포트 상단 `교체 검수` 버튼에서 바로 출입 후보로 이동한다.
- 퇴장 경로의 기존 기록이 하나로 확인되면 시스템이 종료할 분석번호를 제공한다. 검수자는 OUT/IN 장면만 선택하며 번호를 다시 입력하지 않는다. 기존 소유권이 불명확한 경로에는 번호를 추측해 넣지 않는다.
- 재탐지 후보를 검수 전용으로 보류한 경우 실제 이유를 표시한다. 이를 팀 색상 충돌이나 재진입 불확실로 표시하지 않는다. 출입 연결 확인과 이후 추적 단절은 별개로 남는다.
- 재탐지 CLI는 선택적으로 CUDA half precision 및 두 타일 배치를 지원하고 사용 여부를 결과 provenance에 기록한다. 정규화 좌표 반올림으로 한 픽셀 달라지는 타일 폭을 맞춰 불필요한 정사각 패딩을 줄인다.
- 19경기 우선 배치는 12경기의 출입 후보 누락을 먼저, 나머지 7경기의 인원 부족·재진입 의심 구간을 다음으로 처리한다. 최신 로그·스냅샷에 고정된 별도 결과만 저장하며 기존 스냅샷과 수동 결정은 덮어쓰지 않는다.
