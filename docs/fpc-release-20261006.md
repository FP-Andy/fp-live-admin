## 검증

실제 앱 인증/미들웨어를 통과한 SQLite 검사와 별도 PostgreSQL 16 검사를 분리한다. PostgreSQL에서는 동시에 같은 농구 revision을 저장하면 하나만 승인되는 것과, 운영권 행 잠금 해제 후 새 소유권으로 쓰기를 판정하는 것을 확인했다. 스냅샷은 메모리 객체 저장소로 부분 실패를 주입한다. 브라우저는 실제 화면·IndexedDB·localStorage를 사용하고 운영 API 및 외부 네트워크 요청을 차단한 fixture만 사용한다. 공개 화면과 운영 컨테이너 상태 확인은 배포 후 별도 기록한다.

검사 진입점은 `.github/workflows/regression-checks.yml`에 둔다. 주요 추가 검사: `test_match_write_access.py`, `test_outbox_recovery.py`, `test_analysis_snapshots.py`, `test_fla_video.py`, `test_manual_clip_results.py`, `test-draft-ownership-ui.cjs`, `test-fla-recording-recovery-ui.cjs`, `test-basketball-persistence.cjs`, `test-basketball-recovery-ui.cjs`.

## 운영 적용과 남은 범위

- 현재 승인 범위의 배포는 수동 절차로 수행한다. 소스 백업의 실제 복원, DB dump의 별도 PostgreSQL 복원, 이전 컨테이너 이미지 보존 후 api/web만 교체한다. 녹화 서비스·DB·미디어 원본을 중단하거나 삭제하지 않는다.
- 열린 구형 농구·축구 기록 탭은 새로고침이 필요하다. 버전 없는 구형 쓰기로 새 기록을 덮어쓰는 방식의 호환은 허용하지 않는다. 이전 공용 브라우저 초안은 관리자 복구 안내를 따른다.
- 기존 외부 수신자의 v2 적용·재조회 수렴은 실제 수신자 검증까지 완료로 표시하지 않는다. 이번 운영 점검에서 등록된 webhook subscription은 0개였지만 환경변수 기본 수신자 및 외부 구현은 별도 범위다.
- **W16 다중 전송 워커 점유/대상별 순서, W17 로컬 AI·오버레이 장기 작업 lease/fencing은 이번 코드에 포함하지 않았다.** 신규 상태 계약을 먼저 검증한 뒤 별도 변경으로 진행한다. 현재 운영 데이터에서 AI/오버레이 처리 중 작업은 없었다. W18 배포 workflow 연결은 사용자 보류 상태다. 전체 24개 백로그 완료를 의미하지 않는다.
