# FPC 로컬 디자인 검토

세 터미널에서 `apps/web` 디렉터리를 기준으로 실행합니다.

먼저 [계정 준비 절차](console-access.md)에 따라 비공개 관리자 파일을 준비합니다. 로컬 인증 서버는 FastAPI·SQLAlchemy·openpyxl이 설치된 `runtime/auth-venv`를 사용합니다.

```sh
npm run preview:auth
```

```sh
npm run preview:api
```

```sh
npm run preview:ui
```

- 대시보드: http://localhost:4318/admin/dashboard
- FLA 예시 경기: http://localhost:4318/admin/match/demo-fla
- 로그인은 제공한 엑셀의 관리자 아이디/비밀번호를 사용합니다. 운영자 로그인을 검토하려면 관리자 로그인 후 System → 계정 · 접근에서 코드를 설정합니다. 임의 관리자 로그인은 허용하지 않습니다.
- 샘플: 파인 FC vs 루덴스 FC, 전반 24:18, 초기 슈팅 2건, 샘플 선수 명단과 경기 일정.
- 타이머, 점유 팀, 공격 방향, 슈팅 기록, 데이터 내보내기 등을 로컬 메모리에서 확인할 수 있습니다. API 재시작 시 초기화됩니다.
- 예시 xG/xGOT와 경기 흐름 차트는 디자인 검토용 샘플이며 운영 분석 모델의 결과가 아닙니다.
- 샘플 서버는 127.0.0.1에만 바인딩합니다. 운영 서버·DB에 연결하지 않습니다. 계정과 세션은 로컬 SQLite에 저장하며 인증 라우터는 운영 코드와 동일합니다. 지원하지 않는 작업은 오류를 반환합니다.

## UX 변경과 검토 범위

- 공통: 계정 블록 제거, 사업자 정보는 사이드바 하단에 표시, 사이드바 내부 스크롤 제거, 제품별 메뉴 펼치기, 모바일 기본 접힘, 사이드바 접힘 설정 유지.
- 대시보드: 소개 문구 제거, 운영 현황과 경기 등록 작업을 바로 표시.
- FLA: 타이머 상단 고정, 점유/공격 입력 우선 배치, 중복 공격 입력 통합, 설정과 전후반 제어 분리.
- 모바일 FLA: 하단 `경기 제어 / 슈팅 / 기록 / 설정` 전환, 입력 상태 유지, 44px 이상 조작 영역, 가로 넘침 대응.
- 슈팅: 입력 후 맨 아래에서 기록, 저장 중 중복 제출 방지, 실패 시 입력 유지.
- 실제 운영 API/송출/외부 파일 업로드는 로컬 샘플로 검증하지 않습니다. 배포 전 해당 연동 검증이 별도로 필요합니다.

## 확장된 운영 화면

- Media: 경기 검색, 송출/점검 상태 필터, 연결 정보 펼치기.
- Live Coder: 경기 검색, 스코어보드 표시 상태 필터.
- System: 알림 우선 배치, 서버·미디어·GPU·작업 이력 목차, 운영 안내 접기.
- FPA Model Room: 모델 선택 상태, 버전 업로드 접기, 로딩 실패 시 재시도.
- FPA Replay: 팀 검색, 장면 바로 이동, 이전/재생/다음, 작은 화면에 맞는 피치와 지표 배치.
- FPA Code Guide: 코드/액션 검색과 유형 필터, 참고 내용 목차.
- FCM: 공통 제작 단계 내비게이션, 제출 상태 필터, 미제출 팀의 다음 작업 안내, 템플릿 검색/사용 상태 필터, 새 템플릿 등록 접기, 가이드 목차와 FAQ.
- Data Hub: 경기/대회/데이터 종류 필터, 데이터가 있을 때 다운로드 제공, 모바일 행 카드.
- 캘린더: 도구 버튼·경기 정보·담당자 정보 사이 간격 확대.

미리보기 API에는 송출 정상/점검 예시, 보관 경기, 팀 제출 1건, 카드 템플릿, 모델 분포와 리플레이 3개 장면이 포함됩니다. 이 페이지들의 파일 업로드/카드 생성/서버 제어는 실제 서비스와 연결하지 않습니다.

## 검증

- TypeScript 검사와 Next.js 프로덕션 빌드 통과. 기존 `globals.css`의 `align-items: end` 호환성 경고는 남아 있습니다.
- 지정된 11개 페이지를 데스크톱과 약 394px 모바일 폭에서 확인했고 페이지 가로 넘침이 없었습니다.
- 경기/템플릿/코드 검색, 미제출 필터와 초기화, 템플릿 매칭, 모델 전환, 리플레이 장면 이동, 가이드 목차와 FAQ를 예시 데이터로 확인했습니다.
- 사이드바 내 사업자 정보 표시 및 내부 스크롤 없음, 캘린더 도구 아래 24px 여백을 확인했습니다.

## 계정 및 외관 추가 변경

탭별 역할 아이콘, 로그인 문구 가운데 정렬, 관리자/운영자 로그인 분리, System 접근 관리, 다크/화이트 모드 전환을 추가했습니다. 세부 정책과 배포 전 비공개 파일 준비는 [계정 문서](console-access.md)를 참고합니다.

## KFA 명단 / 팀 로고 추가 검토

- 사이드바 **Fine Play**는 로컬 Giants Inline WOFF2를 사용합니다. 폰트 라이선스 전문을 함께 포함했습니다.
- 화이트 모드 운영 현황의 카드 안쪽 여백, 카드 사이 간격, 제목과 숫자의 간격을 조정했습니다.
- 로컬 인증 서버에 `pypdf==6.10.0`, `Pillow==11.1.0`, `python-multipart==0.0.12`도 설치해야 합니다. PDF 파서와 팀 로고 API는 운영 코드와 동일합니다.
- PDF 명단 업로드 결과는 무시된 로컬 파일 `runtime/preview-lineup.json`에 저장하며 API 재시작 후에도 예시 경기에서 복구합니다. 이 파일이 있으면 예시 팀명·명단을 해당 PDF 값으로 표시합니다.
- 팀 로고 등록·교체·해제는 로컬 SQLite와 `runtime/broadcast/logos`에만 반영합니다. 예시 경기의 대회는 `DEMO`이므로 자동 로고 연결을 검토할 때 해당 대회를 선택합니다.
- [예시 Broadcast 설정](http://localhost:4318/broadcast/matches/demo-fla), [실제 슈팅 비교 그래픽](http://localhost:4318/overlay/football/demo-fla/analysis?render=SHOTS_COMPARISON)에서 PDF 색상을 볼 수 있습니다. 등록되지 않은 로고는 기본 FC 아이콘으로 표시합니다.
- 미리보기의 PNG 아카이브 생성/외부 게시와 Broadcast 경기별 로고 업로드는 연결하지 않습니다. 공용 팀 로고, PDF 파싱과 자동 색상, 경기별 색상 변경 및 자동 복귀를 검토할 수 있습니다.
- 웹 빌드 및 API 20개 테스트 통과. 화이트 대시보드·모바일 명단/로고 폼·실제 Broadcast 그래픽의 색상 적용을 확인했습니다. Chrome 확장 프로그램의 파일 URL 접근 설정 때문에 자동 파일 선택은 검증하지 못했으며, 파일 수신·검증·저장은 API 테스트로 검증했습니다.

상세 사용법과 저장 구조는 [팀 브랜딩 문서](team-branding.md)를 참고합니다.
