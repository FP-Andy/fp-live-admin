# AWS FPA 처리 속도 점검

## 측정 조건과 원인

- 기존 g4dn.xlarge / Tesla T4, 4 vCPU. 실제 실행 중 GPU 사용률 8%, FPA CPU 약 172%, 하이라이트 워커 0%였다.
- 동일한 업로드 원본, 작업자가 저장한 코트·색상·13명 설정, YOLO26s, 1280 입력, confidence 0.1, 초당 약 15샘플을 유지했다. 전체 분석은 중지하고 서로 간섭하지 않도록 짧은 구간을 비교했다.
- 3초 구간 cProfile: 색상 추출 15.886초, YOLO predict 2.337초, 영상 읽기 1.208초, 미리보기 쓰기 0.757초. 프로파일링에는 측정 오버헤드가 있으므로 아래 실제 속도 비교와 구분한다.
- 색상마다 픽셀 배열 전체를 다시 골라 평균을 구하는 반복과, 중복 검출 제거/팀 할당에서 같은 색상 분류를 두 번 호출하는 것이 주요 병목이었다.

## 적용한 변경

RGB 512구간의 개수와 채널 합을 `bincount`로 한꺼번에 계산한다. 원본 픽셀, 배경 제거, RGB 반올림, 가중치, 판정 임계값을 그대로 유지한다. 같은 검출의 분류 결과를 중복 제거와 팀 할당이 공유한다.

모델, 정밀도, 검출 해상도, 분석 FPS, 코트 범위, 트래커 기준, 미리보기 품질은 변경하지 않았다. 특정 경기·선수·트랙·색상에 대한 하드코딩은 없다.

## 결과

동일한 5초 구간 / 75개 분석 프레임, 프로파일러 없이 별도 프로세스로 측정:

| 항목 | 기존 | 적용 코드 |
| --- | ---: | ---: |
| 추적·미리보기 처리 | 32.352초 | 16.596초 |
| 처리량 | 2.318프레임/초 | 4.519프레임/초 |
| 프로세스 전체 | 37.168초 | 21.500초 |

약 1.95배 개선. 모든 분석 프레임의 좌표, 트랙 ID, confidence, 색상 표현, 트랙 요약이 정확히 같았다. 무작위 RGB·경계값·비연속 배열의 히스토그램도 기존 평균과 정확히 일치했다. 색상·팀 분류·트래커 회귀 검사를 실행했다.

추가 색상 거리 캐시는 같은 구간에서 4.37프레임/초로 실익을 확인하지 못해 적용하지 않았다.

전체 13,645프레임을 4.519프레임/초로 환산하면 약 50분이다. 짧은 구간을 이용한 추정이므로 전체 경기 처리 시간으로 보장하지 않는다. CPU 색상 처리를 줄였지만 영상 디코딩·색상 처리·추론·미리보기의 직렬 실행은 남아 있다. 여러 단계를 겹쳐 실행하는 구조와 배치 추론은 별도 정확도 검증이 필요하다.
