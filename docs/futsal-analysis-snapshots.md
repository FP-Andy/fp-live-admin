# 풋살 분석 완료 스냅샷

FPA 히트맵의 **분석 완료 판정**에서 선수별 유효 관측률·최장 공백과 FPA 행 수를 확인하고 확정한다. 연결 재계산 중이거나 미반영 검수가 있으면 확정할 수 없다. 관측률 하한을 임의로 통과 기준으로 삼지 않는다. 사람의 검수 완료 판정이며 신원 정확도의 자동 인증이 아니다.

히트맵 좌표·공통 눈금·선수 명단, 같은 서버 검수 버전의 FPA 행/로그, 검수 원본, 경기 연결과 품질 요약을 고정한다. 이벤트가 없으면 완료 확인창에 빈 이벤트맵이라고 명시한다. FPA 작업 화면에 저장한 이벤트를 사용하며, 별도 경기 FPA 기록을 자동 혼합하지 않는다.

- `POST /api/futsal/analysis-snapshots`: S3 `fpa-cv/snapshots/{id}/result.json`에 저장하고 DB `FpaCvResource(kind=analysis_snapshot)`에 목록·버전·체크섬을 보관한다.
- `GET /api/futsal/analysis-snapshots[?job_id=...]`: 접근 가능한 확정본 목록.
- `GET /api/futsal/analysis-snapshots/{id}`: 체크섬 확인 후 읽기. 수정·덮어쓰기 API는 없다.
- 같은 분석을 다시 확정하면 v2, v3 등 새 버전이 생긴다. 서버 검수 버전, 계산 차수, 초기 설정/명단과 좌표를 검증하며 동일 저장 요청 재시도는 중복 생성하지 않는다.
- FCM의 **완료된 분석**에서 두 지도 자료를 함께 가져온다. 불러온 지도 자료는 고정하고 선수 정보·공격 방향·코멘트는 별도 리포트 사본에서 편집한다. 사본의 `sourceSnapshot`과 PDF 하단에 확정 버전이 남는다.

분석 스냅샷은 서버/S3에 저장된다. FCM에서 이후 편집하는 문구는 기존 브라우저 초안·JSON/PDF 저장 방식을 유지한다. 리포트 문구 자체의 서버 최종본 보관은 이번 분석 원본 확정과 별개다. S3 설정이 없거나 쓰기가 실패하면 완료 성공으로 표시하지 않는다. 배포 전 로컬 API 테스트는 격리 SQLite와 메모리 S3, 브라우저 검증은 합성 데이터를 사용한다.

운영 반영 전: 기존 S3 역할의 `fpa-cv/*` 권한을 사용한다. 신규 테이블·마이그레이션·GPU 재분석은 필요 없다. 운영 S3에 실제 쓰는 검증은 아직 하지 않았다.
