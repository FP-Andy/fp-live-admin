# 씬모션 화면·MP4 통일

기존 다운로드는 Python/Pillow가 별도로 그린 녹색 피치, 원형 선수, 별도 공·글꼴·슛 타이밍을 사용했다. 콘솔의 `SceneMotionView`는 디자이너 피치와 육각형/원형 마커, SVG 공, Giants 글꼴을 사용하므로 두 결과가 달랐다.

MP4도 동일 `SceneMotionView`와 `/scene/` 자산을 직접 캡처한다. 재생과 캡처는 하나의 시간 계산 함수를 공유한다. 이동 셰브론 페이드도 절대 시각으로 계산해 렌더 속도와 관계없이 같은 프레임을 만든다. 불필요해진 Python 그림 코드는 제거했다. 채점 및 sceneState→sceneData 변환은 유지한다.

- 1708×1106, 25fps, H.264/yuv420p, BT.709, CRF 12. 피치 원본의 2562:1659 비율을 정확히 유지한다. MP4 코덱의 색 양자화까지 무손실이라는 뜻은 아니다.
- 결과 키에 `fpc-native-v1`을 포함한다. 기존 객체는 삭제하지 않으며 새 조회·다운로드는 새 버전만 참조한다. 장면을 열면 필요한 MP4가 생성되고 이후에는 재사용한다.
- 서버는 같은 장면 생성이 겹치지 않도록 대기 후 캐시를 다시 확인한다. 웹 캡처는 한 번에 하나이며, 대기·최대 실행 시간·임시 파일 정리를 제한한다. 실패하면 구형 디자인으로 대체하지 않는다.
- 내부 렌더 API는 `SCENE_MOTION_RENDER_TOKEN`이 설정되어야 동작한다. API와 웹에 같은 값을 설정하며 토큰을 브라우저에 보내지 않는다. `SCENE_MOTION_RENDER_URL` 기본값은 Docker 내부 웹 주소다. 별도 하이라이트 worker에서 렌더하려면 접근 가능한 사설 URL과 같은 토큰을 별도로 설정해야 한다.
- 화면 캡처는 loopback 페이지·로컬 자산만 읽으며 외부 네트워크와 서비스 워커는 차단한다. 사용자 영상이나 원본을 캡처 서버에 올리지 않는다.

검증: `test_scene_motion_renderer.py`는 버전·기존 객체 보존·캐시·실패·응답 유효성 검사, `test-scene-motion-mp4.cjs`는 실제 화면→MP4→디코딩 프레임을 비교한다. 원정팀 육각형/번호, 성공·실패 패스, 드리블·침투, 오른쪽 슛, 왼쪽 캐칭·오른쪽 펀칭, 클리어를 다룬다. 운영 반영 뒤 별도 로그에 배포 버전과 실제 기존 장면 재생성을 기록한다.
