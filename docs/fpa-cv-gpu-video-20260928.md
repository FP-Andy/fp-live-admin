# FPA GPU 미리보기 인코딩

## 변경 범위

CUDA 분석에서 미리보기를 CPU `libx264` 대신 NVIDIA `h264_nvenc`로 저장한다. YOLO26s 가중치·추론 정밀도·입력 크기·분석 FPS·디코딩·색상 및 트래커 로직은 변경하지 않았다. 검출은 계속 원본 프레임을 사용하므로 미리보기 압축이 선수 판정에 입력되지 않는다. NVDEC, 배치 추론, TensorRT는 이번 변경에 포함하지 않는다.

`--preview-encoder auto`는 실제 출력 크기의 테스트 프레임을 인코딩해 NVENC가 작동하는지 먼저 확인한다. 실패하면 시작 전에 기존 CPU 인코더로 대체한다. `cpu` / `gpu` 옵션으로 동일 조건 비교가 가능하며, 명시한 GPU 모드는 실패를 숨기지 않는다. 실행 중 인코딩 실패는 결과를 공개하지 않는 기존 정책을 유지한다. CPU/MPS에서는 기존 인코더 경로를 유지한다.

NVENC 설정은 H.264 High / p4 / HQ / VBR CQ26 / yuv420p다. 출력 해상도, 원본 FPS, 프레임 개수, MP4 faststart는 유지한다. Compose에서 `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video`를 명시한다. NVIDIA는 [video capability](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html#driver-capabilities)와 [FFmpeg GPU 영상 처리](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)를 문서화한다.

## 검증 방식

기존 T4 / 4 vCPU에서 저장된 사용자 초기 설정을 그대로 사용했다. 운영 분석의 프로세스 트리를 잠시 정지하고 별도 컨테이너에서 순차 비교한 뒤 이어갔다. 운영 분석의 진행분을 삭제하거나 처음부터 재시작하지 않았다. 운영 API는 계속 살아 있으며 테스트는 원본/설정 저장소를 읽기 전용으로 마운트했다.

10초 구간 / 분석 프레임 150개 / 미리보기 300프레임을 비교했다. `frames`, `tracks`, `video`, `detector` JSON의 완전 일치, H.264 전체 디코딩, MP4 faststart 및 FPS를 검사했다. 영상끼리의 픽셀 일치 대신 원본을 같은 크기로 줄인 300프레임 전체와 비교해 압축 품질을 측정했다. 손실 압축 방식이 다르므로 미리보기 바이트가 같다고 주장하지 않는다.

GPU와 CPU 실제 인코딩·재생, 중단 시 프로세스 및 부분 파일 정리, 인코더 실패, GPU 탐지 실패 시 CPU 대체, 탐지 시간 제한을 테스트한다.

## 최종 결과

| 항목 | 기존 CPU 미리보기 | GPU 미리보기 CQ26 |
| --- | ---: | ---: |
| 추적·미리보기 처리 시간 | 25.245초 | 20.766초 |
| 처리량 | 5.942 fps | 7.223 fps |
| 프로세스 전체 | 31.016초 | 26.531초 |
| 미리보기 크기 | 6,723,702 bytes | 7,480,966 bytes |
| 원본 축소 프레임 대비 PSNR | 32.626 dB | 33.575 dB |

최종 GPU 설정은 약 18% 시간 단축 / 22% 처리량 증가다. 기준 실행과 최종 GPU 실행 사이에 압축 설정 비교가 있었으며, 모든 속도 측정에서 운영 분석을 일시정지했다. 최종 300프레임의 원본 대비 오차는 기존보다 작았고, 파일은 약 11% 커졌다. 이 수치는 해당 구간의 측정값이며 모든 영상의 품질이나 압축률을 보장하지 않는다.

검출·트랙·색상·메타데이터 JSON은 완전히 같았다. CUDA 환경에서 테스트 7개(실제 CPU/GPU 인코딩·중단 하위 검사 포함)를 통과했다. 전체 13,645개 분석 프레임으로 환산하면 약 31.5분이며, 아직 전체 경기 실측은 아니다.

## 운영 적용

진행 중 분석은 이미 불러온 CPU 인코더로 계속 처리한다. 워커를 재시작하지 않고 호환되는 PreviewWriter를 먼저, 실행 진입점을 다음으로 원자적으로 교체해 다음 분석부터 GPU 미리보기를 사용한다. 동일 코드로 배포 이미지를 빌드해 후속 컨테이너 생성에도 반영한다. 현재 컨테이너에서도 NVENC의 실제 동작을 확인했다. Compose의 video capability는 이후 컨테이너 생성 시 명시적으로 적용된다. 워커를 재생성해 현재 진행분을 버리지 않는다.
