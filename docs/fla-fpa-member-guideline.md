# FLA/FPA 학회원 운영 가이드

이 문서는 학회원들이 `Fine Play Console`에서 `FLA`와 `FPA`를 사용할 때 같은 기준으로 경기 운영과 퍼포먼스 기록을 진행하기 위한 가이드입니다.

- `FLA`: 경기 페이지에서 실시간 경기 상태, 점유율, 공격 방향, xG/xGOT, 라인업을 조작하고 저장하는 운영 도구
- `FPA`: 경기 중 또는 경기 후 선수별 액션을 코드로 기록하고, 기록된 로그를 분석 파일로 내보내는 분석 도구

운영 콘솔은 권한을 받은 계정으로 로그인한 뒤 사용합니다. 로그인 키나 내부 계정 정보는 별도 공지된 최신 값을 따르고, 문서나 단체 채팅에 공개적으로 남기지 않습니다.

## 1. 기본 원칙

### 경기 전

1. 담당 경기, 홈/어웨이 팀, 대회 클래스, 라운드가 맞는지 확인합니다.
2. FLA에서 경기 페이지가 열리는지 확인합니다.
3. FPA를 함께 사용할 경우 FPA `Live Logger`에서 같은 경기를 불러올 수 있는지 확인합니다.
4. 라인업 PDF가 있는 경우 FLA 경기 페이지에 업로드하거나, 인식이 불안정하면 수동 입력으로 보완합니다.
5. 기록 담당자는 경기 시작 전 역할을 나눕니다.
   - FLA 담당: 경기 페이지 조작
   - FPA 담당: 액션 코드 기록
   - 검수 담당: 라인업, 팀 방향, 기록 누락 확인

### 경기 중

1. 조작은 한 명의 담당자가 일관되게 진행합니다.
2. 홈/어웨이, 전후반, 공격 방향을 바꾸기 전에는 화면 상태를 한 번 확인합니다.
3. 실수로 입력한 기록은 바로 수정합니다. 시간이 지나면 어떤 상황의 기록인지 헷갈리기 쉽습니다.
4. 시스템이 느려지거나 저장 실패 메시지가 보이면 같은 버튼을 반복해서 누르지 말고 담당자에게 공유합니다.

### 경기 후

1. FLA에서 `Export Match Data`로 경기 데이터를 내려받을 수 있는지 확인합니다.
2. FPA에서 `저장` 또는 `분석 및 내보내기`를 완료합니다.
3. 기록 누락, 팀 방향 오류, 라인업 오류가 있었는지 간단히 메모합니다.

## 2. FLA 가이드

FLA의 핵심은 `경기 페이지 조작`입니다. 경기 페이지는 실시간 경기 운영 화면이며, 점유율과 공격 이벤트가 이후 데이터와 리포트의 기준이 됩니다.

### 2.1 진입 흐름

1. 로그인 후 `FLA > Dashboard`로 이동합니다.
2. 담당 경기를 선택해 경기 페이지로 들어갑니다.
3. 경기 페이지 상단에서 홈/어웨이 팀명이 맞는지 확인합니다.
4. 쓰기 권한이 필요하면 `Acquire Lock`을 누릅니다.
5. 화면 상단의 상태가 `write`인지 확인합니다.

`Acquire Lock`은 동시에 여러 명이 같은 경기 상태를 바꾸는 것을 막기 위한 장치입니다. 실제 조작 담당자만 lock을 잡고, 관찰자는 read-only 상태로 보는 것이 안전합니다.

### 2.2 경기 시계 조작

경기 시계는 모든 이벤트의 기준 시간입니다.

- `Start/Pause`: 경기 시계를 시작하거나 멈춥니다.
- `Space`: 시작/일시정지 단축키입니다.
- `Mark 2H Start`: 후반 시작 지점을 표시합니다.

운영 원칙:

- 실제 경기 시작과 동시에 시계를 시작합니다.
- 하프타임, 중단, 장기 지연 상황에서는 담당자끼리 기준을 정한 뒤 조작합니다.
- 후반 시작 시에는 `Mark 2H Start`를 눌러 전후반 표시가 어긋나지 않게 합니다.

### 2.3 점유율 조작

점유율은 `Possession` 영역에서 조작합니다.

- `Home`: 홈팀 점유
- `Away`: 어웨이팀 점유
- `Loose Ball`: 어느 팀도 확실히 점유하지 않는 상황
- 단축키: `Q` = Home, `W` = Away, `E` = Loose Ball

기록 기준:

- 공을 안정적으로 소유하거나 다음 플레이를 통제하는 팀을 선택합니다.
- 경합, 세컨볼, 클리어 직후처럼 소유가 불명확하면 `Loose Ball`을 사용합니다.
- 버튼을 누르는 순간부터 다음 상태 변경 전까지 해당 점유 구간으로 기록됩니다.
- 잘못 눌렀다면 즉시 올바른 팀으로 바꿉니다.

주의:

- `Reset`은 점유율 기록을 초기화하는 위험 액션입니다. 경기 중에는 담당자 합의 없이 누르지 않습니다.
- `Possession Timeline Log`의 `Reset Log`는 화면에 보이는 타임라인 로그 표시를 비우는 기능이며, 경기 데이터 초기화와는 다릅니다.

### 2.4 공격 방향 기록

공격 방향은 팀이 어떤 레인으로 공격했는지 남기는 기록입니다.

1. 이벤트 팀을 `HOME` 또는 `AWAY`로 선택합니다.
2. 레인을 선택합니다.
   - `LEFT`: 왼쪽
   - `CENTER`: 중앙
   - `RIGHT`: 오른쪽
3. `Record Lane`을 눌러 저장합니다.

단축키:

- `A`: LEFT
- `S`: CENTER
- `D`: RIGHT
- `Enter`: 현재 선택된 레인 저장

기록 기준:

- 공이 전진하거나 공격이 전개된 주된 방향을 기준으로 합니다.
- 좌우 기준은 화면과 팀 공격 방향을 혼동하지 않도록 경기 전 담당자끼리 맞춥니다.
- 애매하면 중앙 전개인지, 측면 전개인지 먼저 판단합니다.

### 2.5 xG/xGOT 입력

xG 입력은 슈팅 이벤트를 기록하는 영역입니다. 슈팅 좌표, 선수, 옵션이 이후 분석에 직접 반영됩니다.

기본 흐름:

1. `xG Input`에서 팀을 선택합니다.
2. 라인업이 등록되어 있으면 슈팅 선수를 선택합니다.
3. 슈팅 위치를 피치에서 찍습니다.
4. 필요하면 `Estimate xG`로 xG 값을 계산합니다.
5. 유효 슈팅이면 `On Target` 관련 옵션을 체크하고 골문 위치를 찍어 `Estimate xGOT`를 계산합니다.
6. `Goal`, `Header`, `Difficult`, 압박/1대1 등 해당 옵션을 체크합니다.
7. `Record xG`로 저장합니다.

기록 기준:

- 슈팅 위치는 실제 슈팅이 발생한 지점에 가깝게 찍습니다.
- 골이면 반드시 `Goal`을 체크합니다.
- 헤더 슈팅은 `Header`를 체크합니다.
- 어려운 자세, 약발, 불안정한 슈팅은 화면의 `Difficult` 성격 옵션을 사용합니다.
- 유효 슈팅이 아닌 경우 xGOT는 기록하지 않아도 됩니다.

### 2.6 라인업 입력

라인업은 xG 선수 선택과 경기 데이터 정합성에 중요합니다.

PDF 업로드:

1. `Lineup PDF first team`에서 PDF에 먼저 나오는 팀이 `HOME`인지 `AWAY`인지 선택합니다.
2. `Upload Lineup PDF`를 눌러 PDF를 업로드합니다.
3. 파싱 결과의 HOME/AWAY 선수 수와 이름을 확인합니다.

홈/어웨이 반전:

- PDF에서 홈/어웨이가 반대로 들어갔다면 `Swap` 기능으로 뒤집습니다.
- 반전 후 선수 수와 팀별 명단이 맞는지 다시 확인합니다.

수동 입력:

- PDF 인식이 실패하거나 일부 선수가 누락되면 수동 입력을 사용합니다.
- 등번호와 이름은 가능한 실제 라인업 표기와 맞춥니다.

### 2.7 데이터 내보내기

경기 후에는 `Export Match Data`를 사용합니다.

내보내기 데이터에는 대체로 다음 기록이 포함됩니다.

- 경기 메타 정보
- xG 이벤트
- 공격 방향 이벤트
- 점유율 구간
- dominance 집계

다운로드 후 파일이 열리는지 확인하고, 필요하면 경기명/라운드 기준으로 파일명을 정리합니다.

## 3. FPA 가이드

FPA의 핵심은 `Live Logger 조작`과 `Code Guide 기준 기록`입니다. FLA가 경기 전체 흐름을 기록한다면, FPA는 선수 단위 액션을 더 자세히 남기는 도구입니다.

### 3.1 진입 흐름

1. 로그인 후 `FPA > Live Logger`로 이동합니다.
2. FLA에서 생성된 경기를 쓰는 경우 `경기 불러오기`를 누릅니다.
3. 담당 경기를 선택합니다.
4. Home Team, Away Team, Match ID가 자동으로 들어왔는지 확인합니다.
5. 이전에 저장된 FPA 로그가 있으면 함께 불러와졌는지 확인합니다.

경기를 불러오지 않고 커스텀으로 기록할 수도 있지만, 공식 운영에서는 가능한 FLA 경기와 연결해서 저장하는 것을 권장합니다.

### 3.2 Live Logger 화면 구성

Live Logger는 크게 네 영역으로 나뉩니다.

- 상단 메타 정보: Home Team, Away Team, Match ID, Half
- 기록된 로그: 지금까지 입력한 이벤트 목록
- 축구장: 좌표를 찍는 영역
- Live Controls: Direction, Team, Game Time, Stat Input

좌표 기준:

- 필드 크기는 `105 x 68` 기준입니다.
- 원점은 좌하단 `(0,0)`입니다.
- 필드 위를 클릭하면 좌표가 순서대로 찍힙니다.
- 우클릭하면 마지막 좌표가 제거됩니다.

### 3.3 시간, 팀, 방향 조작

시간:

- `Game Time`은 `MM:SS` 형식으로 입력합니다.
- `-1`, `+1`은 1분 단위로 움직입니다.
- 방향키 단축키:
  - `ArrowUp`, `ArrowRight`: 1분 증가
  - `ArrowDown`, `ArrowLeft`: 1분 감소

팀:

- `Team`에서 Home/Away를 선택합니다.
- Home/Away를 바꾸면 Direction도 함께 뒤집히는 현재 콘솔 동작을 전제로 합니다.

방향:

- `Direction`은 현재 기록하는 팀의 공격 방향입니다.
- 기록 전 현재 팀이 어느 방향으로 공격하는지 반드시 확인합니다.

### 3.4 로그 입력 순서

일반적인 입력 순서는 다음과 같습니다.

1. Half, Team, Direction, Game Time을 확인합니다.
2. 축구장에 필요한 좌표를 찍습니다.
3. `Stat Input`에 코드를 입력합니다.
4. Enter 또는 제출 버튼을 눌러 로그를 추가합니다.
5. 기록된 로그 테이블에서 Time, Team, Player, Action, Tags, Receiver, Pos를 확인합니다.
6. 경기와 연결된 기록이면 중간중간 `저장`을 누릅니다.

좌표 개수 기준:

- 슈팅, 터치, 태클, 인터셉트 등 한 지점 이벤트: 좌표 1개
- 패스, 크로스, 돌파, 스로인, 스프린트 등 시작과 도착이 있는 이벤트: 좌표 2개
- 드리블처럼 이동 경로가 중요한 이벤트: 필요한 만큼 여러 좌표를 찍을 수 있습니다.

### 3.5 로그 수정

기록된 로그에서 행을 선택한 뒤 다음 기능을 사용할 수 있습니다.

- `선택 로그 위로`: 선택한 로그를 위로 이동
- `선택 로그 아래로`: 선택한 로그를 아래로 이동
- `선택 로그 삭제`: 선택한 로그 삭제

수정 원칙:

- 입력 직후 잘못된 로그를 발견하면 바로 고칩니다.
- 시간 순서가 어긋났다면 위/아래 이동으로 정렬합니다.
- 확실히 잘못된 로그만 삭제합니다.

### 3.6 저장과 내보내기

`저장`:

- FLA 경기와 연결된 FPA 로그를 DB에 저장합니다.
- 같은 경기를 다시 불러오면 저장된 로그도 함께 로드됩니다.
- 저장은 현재 화면의 로그를 기준으로 덮어쓰기 방식입니다.

`분석 및 내보내기`:

- 현재 로그를 분석해 엑셀 파일로 내보냅니다.
- 경기 종료 후 최종 산출물 확인용으로 사용합니다.

`수정 및 불러오기`:

- 기존 FPA 엑셀 파일의 `Data` 시트를 읽어 Live Logger 상태로 복원합니다.
- 과거 기록을 이어서 수정할 때 사용합니다.

## 4. FPA Code Guide

FPA 코드는 `선수번호 + 액션코드 + 수신선수번호 + 태그` 형태로 입력합니다.

기본 형식:

```text
선수번호 + 액션코드 + 수신선수번호.태그1.태그2
```

예시:

| 입력 | 의미 | 좌표 |
| --- | --- | --- |
| `10ss8` | 10번 선수가 8번 선수에게 패스 성공 | 2개 |
| `10s8` | 10번 선수가 8번 선수에게 패스 실패 | 2개 |
| `7ss9.k` | 7번 선수가 9번 선수에게 키패스 | 2개 |
| `11ddd.wf` | 11번 선수가 어려운 자세에서 골 | 1개 |
| `9ddd.h` | 9번 선수가 헤더 골 | 1개 |
| `3c` | 3번 선수가 크로스 실패 | 2개 |

### 4.1 슈팅 코드

| 코드 | 액션 | 좌표 | 설명 |
| --- | --- | --- | --- |
| `ddd` | Goal | 1개 | 골 |
| `dd` | Shot On Target | 1개 | 유효 슈팅 |
| `d` | Shot | 1개 | 빗나감 포함 슈팅 |
| `db` | Blocked Shot | 1개 | 블락된 슈팅 |

### 4.2 패스와 찬스 메이킹 코드

| 코드 | 액션 | 좌표 | 설명 |
| --- | --- | --- | --- |
| `ss` | Pass Success | 2개 | 패스 성공 |
| `s` | Pass Fail | 2개 | 패스 실패 |
| `zz` | Assist | 2개 | 어시스트 |
| `z` | Key Pass | 2개 | 키 패스 |
| `cc` | Cross Success | 2개 | 크로스 성공 |
| `c` | Cross Fail | 2개 | 크로스 실패 |

### 4.3 공격 플레이 코드

| 코드 | 액션 | 좌표 | 설명 |
| --- | --- | --- | --- |
| `ee` | Breakthrough | 2개 | 돌파 |
| `rr` | Dribble | 1개 이상 | 드리블 |
| `gp` | Gain | 1개 | 볼 획득 |
| `m` | Miss | 1개 | 컨트롤 미스 |
| `tr` | Throw-in | 2개 | 스로인 |
| `st` | Sprint | 2개 | 스프린트 |

### 4.4 수비와 기타 코드

| 코드 | 액션 | 좌표 | 설명 |
| --- | --- | --- | --- |
| `aa` | Tackle | 1개 | 태클 |
| `q` | Intercept | 1개 | 인터셉트 |
| `qq` | Acquisition | 1개 | 볼 탈취 |
| `w` | Clear | 1개 | 클리어 |
| `ww` | Cutout | 1개 | 차단 |
| `qw` | Block | 1개 | 블락 |
| `v` | Goalkeeper Catching | 1개 | 골키퍼 캐칭 |
| `vv` | Goalkeeper Punching | 1개 | 골키퍼 펀칭 |
| `sv` | Save | 1개 | 골키퍼 세이브 |
| `bb` | Duel Success | 1개 | 경합 성공 |
| `b` | Duel Fail | 1개 | 경합 실패 |
| `f` | Foul | 1개 | 파울 |
| `ff` | Foul Suffered | 1개 | 피파울 |
| `o` | Offside | 1개 | 오프사이드 |
| `t` | Touch | 1개 | 위치 기록 |

### 4.5 수동 태그

태그는 액션 코드 뒤에 `.`으로 붙입니다.

| 태그 | 의미 |
| --- | --- |
| `.k` | Key, 키패스 |
| `.a` | Assist, 어시스트 |
| `.h` | Header, 헤더 |
| `.r` | Aerial, 공중볼 경합 |
| `.w` | Suffered, 파울 당함 |
| `.n` | In-box, 박스 안 |
| `.u` | Out-box, 박스 밖 |
| `.p` | Progressive, 진전 패스 |
| `.c` | Counter Attack, 역습 |
| `.sw` | Switch, 사이드 전환 |
| `.wf` | Difficult, 어려운 자세 |
| `.ft` | First Time, 원터치 |

예시:

- `10ss8.k`: 10번이 8번에게 키패스
- `9dd.h`: 9번의 헤더 유효 슈팅
- `11ddd.c.wf`: 11번의 역습 상황 어려운 자세 골

### 4.6 자동 태그 규칙

일부 태그는 코드와 위치에 따라 자동으로 붙습니다.

| 태그 | 조건 | 예시 |
| --- | --- | --- |
| Success | 액션 코드가 반복되는 성공형 코드 | `ss`, `cc`, `dd`, `ddd` |
| Fail | 실패형 코드 | `s`, `c`, `d` |
| Progressive | 패스가 전진 조건을 충족 | 전진 패스 |
| In-box | 이벤트가 박스 안에서 발생 | 박스 안 슈팅/패스 |
| Out-box | 슈팅이 박스 밖에서 발생 | 중거리 슈팅 |

자동 태그가 있어도, 경기 맥락상 중요한 정보는 수동 태그로 보완합니다.

## 5. 역할별 체크리스트

### FLA 담당자

- [ ] 경기 페이지 진입 후 홈/어웨이 확인
- [ ] `Acquire Lock` 후 write 상태 확인
- [ ] 경기 시작 시 `Start/Pause`로 시계 시작
- [ ] 점유율 Home/Away/Loose Ball 기록
- [ ] 공격 방향 LEFT/CENTER/RIGHT 기록
- [ ] 슈팅 발생 시 xG/xGOT 기록
- [ ] 라인업 PDF 또는 수동 라인업 확인
- [ ] 경기 종료 후 `Export Match Data` 확인

### FPA 담당자

- [ ] `FPA > Live Logger` 진입
- [ ] `경기 불러오기`로 담당 경기 연결
- [ ] Half, Team, Direction, Game Time 확인
- [ ] 좌표 입력 후 코드 입력
- [ ] 기록된 로그 테이블에서 입력 결과 확인
- [ ] 중간중간 `저장`
- [ ] 경기 종료 후 `분석 및 내보내기`

### 검수 담당자

- [ ] 홈/어웨이 팀명이 맞는지 확인
- [ ] 라인업 선수명/등번호 확인
- [ ] FPA 코드 입력 실수 확인
- [ ] 전후반 전환 시점 확인
- [ ] 경기 후 FLA export와 FPA export 생성 여부 확인

## 6. 자주 나는 실수

| 상황 | 문제 | 해결 |
| --- | --- | --- |
| Home/Away를 반대로 기록 | 팀별 데이터가 뒤집힘 | 경기 전 팀 방향과 라인업을 같이 확인 |
| FPA 좌표를 찍지 않고 코드 입력 | 위치 데이터가 비거나 잘못됨 | 코드 입력 전 필요한 좌표 개수 확인 |
| 패스인데 좌표 1개만 찍음 | 시작/도착 위치 분석 불가 | 패스/크로스 계열은 좌표 2개 |
| 팀을 바꿨는데 Direction을 확인하지 않음 | 좌표 해석이 반대로 될 수 있음 | Team 변경 후 Direction 확인 |
| FLA lock 없이 조작하려 함 | 저장 권한 없음 | 조작 담당자가 `Acquire Lock` |
| FPA 저장을 안 함 | 다시 들어왔을 때 로그가 남지 않을 수 있음 | 경기와 연결 후 중간중간 `저장` |
| Reset 버튼을 실수로 누름 | 기록 초기화 위험 | Reset 계열은 담당자 합의 후 사용 |

## 7. 권장 운영 방식

가장 안정적인 운영은 2명 이상이 역할을 나누는 방식입니다.

- 1명: FLA 경기 페이지 조작
- 1명: FPA Live Logger 기록
- 가능하면 1명 추가: 라인업/코드/시간 검수

혼자 운영해야 할 때는 FLA를 우선합니다. FLA의 경기 시계, 점유율, 공격 방향, xG 기록은 경기 전체 데이터의 기준이기 때문입니다. FPA는 가능한 범위에서 주요 액션부터 기록하고, 놓친 세부 액션은 경기 후 영상이나 메모를 기준으로 보완합니다.
