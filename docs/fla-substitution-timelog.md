# FLA 영상 기록의 교체 시각 로그

위치: 풋살 → FLA → 영상 기록, 우측 패널의 슈팅 위협도 기록 바로 아래. 운영 제공.

## 기록 방식

선수 이름·번호·OUT/IN을 요구하지 않는다. 경기 영상과 시작 기준이 저장된 상태에서, 영상 재생 중 `홈 교체 기록` 또는 `어웨이 교체 기록`을 누르면 일시정지하고 원본 영상 시각과 팀을 즉시 저장한다. 경기 시각은 원본 시각에서 킥오프 오프셋을 뺀 값이다. 별도 명단 설정이나 타임로그 시작 단계가 없다.

`시각 직접 입력 · 메모`에서 시각을 보정하거나 동시 교체 등 메모를 남긴다. 기록 후 수정·삭제, CSV/JSON 내보내기를 지원한다. 기록 목록은 기본 접힘이며 건수만 표시한다. 펼쳐도 높이를 최대 280px로 제한해 누적 기록이 입력 패널을 계속 늘리지 않는다. 진행 중인 FLA 경기의 앞으로 탐색 제한과 점유율 집계를 유지한다. 완료·보관된 경기는 자유 탐색하며 교체 로그만 보완하고, 점유율·이벤트 입력은 잠근다. 키보드로 메모·시각을 편집할 때만 기록 단축키를 억제한다.

## 데이터와 호환

`fpa-substitution-log/v2`는 `{id, time, team, note}`만으로 저장한다. `outId`와 `inId`는 두 필드 모두 없을 수 있다. v1 명단/선수 연결 로그도 읽고 보존한다. 선수 미판정 로그는 그대로 판정 대기로 보관하고 확정된 출전 구간으로 꾸미지 않는다. 기존 선수 연결 로그의 팀·시각을 바꾸면 그 연결을 해제한다.

교체 후보용 `reviewWindows`는 원본 시각 전후 15초(영상 범위 내), 팀, `camera-bottom` 경계 힌트를 담는다. 이는 검색 범위일 뿐 실제 교체 순간이나 선수 연결을 확정하지 않는다. 경계 위치는 영상에 지정한 코트 ROI에서 계산할 예정이며 화면 하단의 고정 픽셀로 하드코딩하지 않는다.

미판정 로그 이후 해당 팀의 확정 출전 구간 계산은 중단한다. 벤치 시간을 관측 누락으로 계산하거나 타임로그만으로 두 선수의 좌표를 연결하지 않는다. `trackingApplied: false`를 유지한다. FLA UI는 출전 구간 CSV를 제공하지 않으며 JSON의 appearances도 빈 목록으로 저장한다.

## 다음 연결 단계 — 아직 미구현

1. 같은 원본 영상의 분석 결과·검수 버전과 연결한다.
2. 시간창에서 하단 코트 경계의 안→밖, 밖→안 움직임을 함께 찾는다. 단순한 경계 근접이나 트랙 소멸만으로 교체로 확정하지 않는다.
3. OUT 직전 분석번호, IN 직후 트랙, 계속 남은 동료, 유니폼 연속성을 대조한다. 킥인 복귀·경합·그림자·다중 교체·재출전은 별도로 처리한다.
4. 유일하고 충분한 근거가 있을 때 출입 시각을 각각 찾아 출전 구간을 나눈다. 불명확한 경우 해당 장면 확인 요청을 남긴다.
5. 교체 전후 다른 선수를 같은 번호로 복구하지 않도록 연결 제한을 적용한 뒤 히트맵·보강·리포트를 재계산한다. 기존 스냅샷을 덮어쓰지 않는다.

## 저장·검증

`PUT /api/futsal/fla-video/matches/{id}/substitutions`는 경기별 독립 revision, request id 및 행 잠금을 사용한다. 기존 경기 담당자 권한과 영상 접근 권한은 유지하며, 완료·보관 상태여도 교체 로그만 저장할 수 있다. FLA 기록창 잠금·완료 상태·점유율·이벤트는 변경하지 않는다. DB 마이그레이션은 없다. 진행 중인 영상 기록의 미재생 시각, 부분 OUT/IN 연결, 중복 시각 로그, 다른 영상 로그를 거절한다. 완료 경기나 영상 기록을 시작하지 않은 경기에서는 원본 영상 범위 안의 교체 시각을 직접 입력할 수 있다. 대시보드로 완료한 경기처럼 시작 오프셋이 없으면 원본 영상 시각만 표시하고 경기 시각을 추정하지 않는다. 이 경우 첫 저장 때 브라우저가 읽은 영상 길이를 별도로 고정하고 이후 변경을 거절한다. 전체 기록 초기화와 영상 기준 변경은 타임로그 revision도 올린다.
