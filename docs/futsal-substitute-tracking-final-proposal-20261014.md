# 풋살 교체 선수 추적 개선 최종 반영안

2026년 10월 14일

**YOLO26 초벌 추적을 유지하고, 기존 로그의 오연결 분리와 앞뒤 재연결을 먼저 적용한다. 남은 유실 구간에는 RF-DETR을 선택적으로 실행한다.** 전체 영상의 상시 앙상블은 기본 처리에서 제외하고, 두 모델을 함께 쓸 때의 박스 통합 기능은 선택적 재탐지에 활용한다.

목표는 교체 선수에게 올바르게 귀속되는 실제 관측 시간을 늘리고, 그 결과를 히트맵과 개인 리포트에 연결하는 것이다. 퇴장 선수의 기존 분석번호를 모르는 경우에도 입장 선수가 확인되면 독립된 출전 구간을 만들 수 있어야 한다. 이번 문서는 반영안이며 운영 배포와 전달 PDF 갱신은 결과 검토 후 진행한다.

**판단 근거**

동일한 세 경기에서 교체 선수 1명씩, 15fps로 처리한 12초 영상 중 초기 준비 0.8초를 제외한 11.2초를 비교했다. 합계 평가 구간은 33.6초다. 보간·히트맵 추정을 제외하고 탐지 좌표가 연결된 시간을 집계했다.

| 방식 | 연결된 관측 합계 | 프레임당 탐지 시간 | 결정 |
|---|---:|---:|---|
| YOLO26s 전체 화면 | 24.47초 | 22.98ms | 초벌 기본 유지 |
| YOLO26s 확대 탐지 | 24.60초 | 53.61ms | 작은 객체 등 적합한 실패 유형에 한해 비교 |
| RF-DETR 확대 탐지 | 33.60초 | 214.67ms | 유실 구간 보조 모델 우선 후보 |
| YOLO26 + RF-DETR 단순 결합 | 32.60초 | 268.28ms | 경계 중복을 해결하지 않고 사용하지 않음 |
| YOLO26 + RF-DETR 경계 중복 보정 | 33.60초 | 268.28ms | 선택적 결합 기능으로 유지 |

이 표본의 관측량 증가는 약 37.3%다. RF-DETR과 보정 앙상블의 결과가 같아, 전체 프레임에서 두 모델을 항상 돌릴 근거는 부족하다. 시간은 T4·FP16·실험용 확대 영역 구성에서 측정한 탐지 단계이며 다운로드, 디코딩, 모델 준비, 추적과 리포트 생성 시간을 포함하지 않는다. RF-DETR은 두 영역을 순차 처리했으므로 이 수치를 최적화된 모델의 한계로 보지 않는다.

33개 장면 표본에서 보정 앙상블의 선수 뒤바뀜은 발견하지 못했지만, 전체 출전 구간의 정확도는 아직 검증되지 않았다. 각 실험은 교체 선수 한 명을 기준으로 연결했으므로 모든 선수의 관측 소유권을 동시에 결정하는 검증도 필요하다.

별도 기존 로그 실험에서는 파주 선수의 연결 관측이 3.47초에서 45.38초로 늘었다. 이는 위 11.2초 비교와 다른 구간이다. 마지막 경합에서 두 사람이 합쳐진 박스가 남아 있어, 45.38초 전부를 정확한 위치 관측으로 채택하면 안 된다. [실험 결과](../runtime/ensemble-pilot-20261014/index.html)와 [집계 원본](../runtime/ensemble-pilot-20261014/results.json)에 비교 장면과 수치를 보관한다.

**판정 로직**

1. **박스 품질과 선수 신원을 따로 평가한다.** 같은 선수라는 근거가 있어도 그림자·다른 사람을 포함한 박스의 하단 좌표는 히트맵을 왜곡할 수 있다. 완전한 몸체 박스를 우선하고, 적절한 박스가 없으면 그 시각의 위치는 제외한다. 제외된 시간은 실제 관측으로 세지 않는다.
2. **경합 이전에 분리되어 보였던 두 사람은 하나로 합치지 않는다.** 그림자 중복 제거는 단순히 큰 박스 안에 작은 박스가 있다는 이유로 실행하지 않는다. 같은 팀이라도 과거 분리 관측, 동시에 존재한 위치, 다른 사람의 확정 연결과 충돌하면 병합을 막는다. 확대 경계의 반쪽 박스도 같은 검사를 통과해야 한다.
3. **잘못 이어진 자동 트랙을 먼저 분리한다.** 현재 코드에는 상대 유니폼이 지속되면 이후 연결을 멈추는 처리가 있지만, 이미 잘못 귀속된 관측을 복구하는 기능은 부족하다. 변화 시점의 앞뒤를 나누고, 원래 선수가 옮겨간 다른 트랙을 다시 찾는다. 순간적인 가림이나 조명 변화 하나만으로 분리하지 않는다. 수동 확정과 충돌하는 경우는 자동 변경 대신 검수 대상으로 남긴다.
4. **후속 장면을 이용해 앞쪽 연결도 복구한다.** 후보 점수에는 앞뒤 위치·속도, 지속된 팀 색상, 몸체 형태, 시간 차이, 입장 시각을 사용한다. 후보 경로를 전체적으로 비교하고 한 박스가 두 선수에게 귀속되거나 같은 선수가 동시에 다른 장소에 나타나는 연결을 금지한다. 현재 3.5초 공백 제한만 늘리는 방식은 채택하지 않는다. 공백이 길수록 추가 근거와 후보 간 점수 차이가 필요하다.
5. **약한 탐지는 확인된 경로 안에서 회수한다.** 0.35 미만 탐지를 모두 허용하는 변경은 하지 않는다. 신원이 확인된 앞뒤 관측과 위치·움직임·팀이 일치하고 그림자·중복·다른 선수 충돌이 없을 때만 포함한다. 약한 탐지만으로 새로운 교체 선수를 확정하지 않는다. 기존 파일에 해당 탐지가 저장되지 않았다면 로그 처리만으로는 복구할 수 없으므로 재탐지 대상으로 넘긴다.
6. **색상과 스포츠 맥락은 증거로 사용한다.** 홈·원정·골키퍼·심판의 역할, 선발 인원, 골문과의 거리는 보조 근거다. 한 명이 사라졌다는 이유로 새 객체에 그 번호를 강제 부여하지 않는다. 자동 팀 판정은 여러 장면의 몸체 색상으로 갱신하되 수동 확정은 우선한다. 공격 방향·평균 포지션을 동일인 확정 조건으로 사용하지 않는다.
7. **입장과 퇴장 연결은 독립적으로 관리한다.** 입장이 확인되면 새 분석번호와 출전 구간을 만들고 그 선수의 실제 관측을 누적한다. 퇴장 번호가 불명확하면 이전 선수 중 한 명을 임의로 종료하지 않는다. 두 경로가 같은 관측을 중복 소유하지 않게 하고, 불명확한 꼬리 구간은 검수로 남긴다. 하단 교체선은 강한 단서지만 부상으로 골문 쪽으로 나가는 장면도 시간·경로 증거로 처리한다.
8. **코트 밖 이동은 신원 유지와 히트맵 집계를 분리한다.** 킥인 준비로 잠시 밖에 나간 선수를 곧바로 교체로 처리하지 않는다. 주변 경로는 신원 연결에 활용하고 코트 밖 좌표는 피치 히트맵에서 제외한다. 교체선과 코트 크기는 경기 설정에서 읽고, 영상 회전이나 다른 구장에도 같은 판정 구조를 사용한다. 경기명·트랙 ID·특정 시각 예외를 두지 않는다.

앞뒤 트랙 분리와 재연결은 [GTA-Link](https://github.com/sjc042/gta-link)의 구조를 참고한다. 팀·등번호·경기장 좌표를 함께 고려하는 장기 연결은 [SportsSUSHI](https://arxiv.org/abs/2502.21242)를 참고한다. 두 연구의 ReID·학습 모델 전체를 현재 구현했다고 주장하지 않으며, 이번 범위에서는 기존 좌표·색상·확정 정보를 이용한 방식부터 검증한다. 약한 탐지 회수는 이미 사용하는 [ByteTrack](https://github.com/FoundationVision/ByteTrack)의 연결 원칙과 후처리 필터가 충돌하지 않도록 조정하는 작업이다.

**선택적 재탐지 흐름**

기존 YOLO 결과 읽기 → 중복·오염 박스 판정 → 오연결 분리 → 앞뒤 트랙 재연결 → 남은 유실 구간 선별 → RF-DETR 재탐지 → 공통 추적과 신원 연결 → 검수 → 새 스냅샷 → 히트맵과 PDF.

기존 영상은 전체 초벌 분석을 다시 하지 않고 저장된 결과부터 처리한다. 재탐지 우선순위는 관측 10초 미만 입장 선수, 10~30초 선수, 경합 뒤 급격히 끊긴 선수 순으로 둔다. 현재 기준 목록은 교체 개인 구간 185개 중 30초 미만 61개, 그중 10초 미만 20개이며, 실행 전에 최신 로그로 다시 산정한다. 이후 성능 평가는 짧은 선수만 골라 통계를 유리하게 만들지 않도록 전체 185개와 우선 대상의 결과를 함께 낸다.

재탐지는 마지막 정상 관측과 다음 후보가 포함되도록 앞뒤 여유 구간을 잡고, 안정된 경로를 찾으면 중단한다. 실패하면 탐색 범위를 단계적으로 확장하되 확인된 퇴장·다른 입장 선수의 확정 관측·작업 예산을 넘어 강제로 연결하지 않는다. 아래쪽 교체선뿐 아니라 코트 안의 유실 위치도 검색할 수 있어야 한다. 최초 기준은 실험한 15fps로 두고, 프레임 수를 줄이는 최적화는 별도로 비교한다.

RF-DETR 결과는 기존 YOLO 탐지와 같은 원본 영상 시각·좌표계로 변환한다. 준비 구간의 원본 시각과 잘라낸 영상의 시각 오프셋을 보존한다. 두 모델의 탐지 점수를 동일한 확률로 취급하지 않고, 박스 품질·시간적 일관성을 우선한다. 그림자 박스와 몸체 박스의 좌표를 단순 평균하지 않는다. 재탐지 영역마다 겹치는 준비 구간을 두고 공통 추적기를 실행한 뒤, 기존 분석번호에는 검증된 대응 관계로 연결한다. 새 로컬 트랙 ID를 기존 선수 번호로 바로 사용하지 않는다.

기존 YOLO 탐지 캐시를 재사용할 수 있으면 같은 프레임의 YOLO 추론을 반복하지 않는다. 유실 구간에서 RF-DETR만 새로 실행하고 필요한 원본 박스와 선택적으로 결합하는 구성을 기본 후보로 한다. RF-DETR 단독보다 결합 결과가 나쁜 경우를 회귀 테스트로 유지한다.

현재 측정 구성에서 RF-DETR은 기본 YOLO 탐지 비용의 약 9.34배다. 같은 처리 프레임 수를 가정하면 전체 프레임의 5%에 RF-DETR을 추가할 때 탐지 계산량은 약 1.47배, 10%면 약 1.93배다. 이는 전체 작업시간 예측이 아니다. 초기 자동 복구 예산은 기본 탐지 계산량 대비 추가 50%를 제안하며, 모델 준비·구간 확장·중복 실행도 예산에 집계한다. 초과 항목은 추가 복구 대상으로 표시하고 완료로 처리하지 않는다. 이후 작은 관심 영역, 배치, FP16, 디코딩 재사용의 실측으로 예산을 조정한다.

**웹과 데이터 반영**

- 검수 화면에 `교체 선수 추적 보완` 작업을 연결한다. 먼저 GPU 없이 기존 로그를 복구하고, 추가 탐지가 필요한 구간과 예상 처리량을 보여준다. GPU 단계는 같은 작업에서 이어갈 수 있게 한다.
- 상태는 `로그 복구 중`, `추가 탐지 대기`, `추가 탐지 중`, `검수 필요`, `반영 가능`으로 구분한다. 중단·재개는 완료된 구간을 재사용한다. 같은 영상을 대상으로 겹치는 작업은 합치고, 초벌 분석 및 초기 장면 검출 대기열을 무한히 점유하지 않는다.

같은 여섯 명, 입장 뒤 각 23초 구간에서 기존 배정 관측 합계 30.50초 대비 기존 로그만으로 81.90초를 연결했다. 이 값은 알고리즘이 연결한 실제 탐지 시간이며, 전 프레임 동일인 정답 평가치는 아니다. 부천–충남아산은 3.54→22.93초, 안양–대전은 8.01→22.40초, 수원FC–대전은 2.47→20.82초다. 서울–안양·강원–김해·김포–부천은 여전히 짧아 강제 연결하지 않는다.

위 세 개선 사례에서 각 일곱 시각을 원본 영상으로 대조했고, 채택한 20개 표본에 다른 선수 단독 오연결은 보이지 않았다. 수원FC–대전 마지막 표본은 접촉으로 제외했다. 이 검사는 전체 출전 구간의 정확도를 보증하지 않는다. RF 실험 수치는 확대 탐지와 새로운 추적기를 함께 바꾼 결과라 모델만의 개선량으로 설명하지 않는다.

JS 회귀 여섯 묶음, Python 여섯 검사, TypeScript 검사와 로컬 실제 fixture의 브라우저 계산·복구 UI 표시를 검증한다. 웹에서는 FCM → 매치 리포트 → 교체 검수 → 추적 복구 결과에서 확인한다. 기존 전달 PDF는 일괄 덮어쓰지 않는다.

전체 원시 로그가 있는 **38경기·185명** 재처리도 완료했다. 배정 관측 합계 17,344.52→17,582.84초(+1.37%), 관측 중앙값 57.86→62.66초, 10초 미만 20→18명, 30초 미만 61→60명이다. 접촉·혼합 박스와 재사용 ID 꼬리를 더 엄격히 제외하므로 앞선 v9 후보의 18,084.79초보다 총량은 줄었다. 전 경기의 동일인 정확도 향상을 검증한 수치로 표현하지 않는다.

38경기 모두 자기 시간 중복, 같은 트랙 다중 소유, 출전 구간 초과, 추정 보강 유효성 검사 통과. 광주–경남 홈 #7, 서울–안양 원정 #7·#8의 수동 관측 총 20개는 새 품질 판정과 충돌하여 보존하고 검수 상태로 표시했다. 경남–대구는 이번 로컬 원시 로그 캐시가 없어 회귀 대상에서 제외했다. 판정 규칙은 동일하며 마지막 장면 표시와 불필요한 색상 계산 제거에 따른 코드 해시 두 개가 있다.
