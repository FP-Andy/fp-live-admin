# 풋살 FLA 영상 기록 — 로컬 검토

상태: 로컬 개발, 사용자 확인 전. 운영 배포/운영 경기 생성은 하지 않음.

- Futsal → FLA → 영상 기록. 정규 17 + 파이널 22 = 39경기 명세.
- 일정표 왼쪽 Home, 오른쪽 Away. 9/12 정규 및 파이널 일부, 9/13 파이널 나머지.
- 파이널 4C 서울–김포, 6B 전남–대전 추가. 정규 8F 전남–서울 제외.
- 영상 왼쪽, 기존 FLA 입력 카드 오른쪽. 입력 영역만 세로 스크롤.
- 원본 영상과 시작 기준을 선택한 후 경기 시작. 트래킹/GPU 불필요.
- 실제 미디어 시간으로 경기 시각과 점유 구간을 계산. 배속/정지/버퍼링 반영.
- 시작 이후 앞으로 탐색 금지. 되감기 동안 이벤트 추가 가능, 점유 기록은 유지.
- 기존 최종 기록 시점에 자연 재생으로 도달하면 원래 점유 팀으로 누적 재개.
- Space 재생/정지, Q/W 홈/어웨이, E 루즈볼, A/S/D 공격 위치, Enter 공격 기록.
- 버튼/영상/선택란 초점과 무관하게 단축키 처리. 경기 기록 중 주황색 테두리.
- 저장 요청 ID와 버전으로 재시도/동시 수정 중복 방지. 새로고침 시 저장된 시각에서 정지 상태 복원.
- 기존 Event/PossessionSegment/State 및 경기 흐름 집계를 사용. DB 스키마 변경 없음.
- 실제 S3 소스 API와 영상 삭제 시 FLA 연결 참조 보호 추가.

## 로컬 실행

독립 worktree: /tmp/futsal-fla-video (codex/futsal-fla-video).

API: `python scripts/preview_fla_video.py --video /absolute/original.mp4` (4341).
Web: apps/web에서 `NEXT_DIST_DIR=.next-fla-video NEXT_API_PROXY_TARGET=http://127.0.0.1:4341 NEXT_PUBLIC_FLA_VIDEO_PREVIEW=1 node node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 4340`.
진입: http://127.0.0.1:4340/api/local-preview

이 스크립트는 loopback 전용 로컬 계정과 별도 SQLite를 사용한다. 운영 인증 우회 코드는 운영 앱에 포함하지 않는다.
39경기는 로컬에만 생성. 연결 가능한 영상은 기존 노트북의 약 19초 원본 기능 확인용 샘플 하나이다. 경기명과 실제 샘플 경기의 관계를 의미하지 않는다.
운영 S3 목록/재생 링크의 로컬 반출은 자동 승인 검토가 거절하여 실행하지 않았다. 사용자에게 별도 허용 여부를 질문했다.

## 검증

- TypeScript noEmit 통과.
- VideoClock 4개: 실제 미디어 시간, 되감기/점유 보존, 저장 중 새 구간 보존, 단축키.
- API 4개: 저장 재시도, 과거 이벤트 추가, 겹침/누락/앞으로 점프/동시 수정 차단, 경기 39개 반복 생성, 슛 좌표 및 영상 권한.
- 기존 풋살 경기 흐름 집계 5개 회귀 테스트 통과.
- 실제 브라우저: 원본 재생, 시작 기준 저장, 경기 시작, 선택란에서 Space 정지, 되감기 뒤 W/A/Enter 공격 추가, 슈팅 추가, 앞으로 탐색 차단 확인.
- 기존 점유 100% Home인 상태에서 과거 Away 이벤트를 추가해도 점유 유지 확인.
- 전체 페이지 높이는 뷰포트 높이와 동일하고 우측 입력 컨테이너에만 스크롤 생성 확인.

## 배포 전 남은 확인

1. 사용자 UI 확인.
2. 허용받은 S3 실영상의 이름/회차/팀과 39경기 매칭 확인. 자동 후보는 동일 회차·라운드·Home/Away 순서가 모두 맞는 경우만 제안한다.
3. 기존 운영 FLA 경기와 중복되는 대상이 있는지 대조 후 경기 생성. 기존 FLA 기록이 있으면 새 시작 기준 덮어쓰기를 막는다.
4. 운영 도메인의 허용 Origin 및 S3 리다이렉트/Range 재생 확인.
5. 배포 후 소수 경기 검증, 이후 나머지 연결.

## 사용자 검토 후 보완 — 매치컨트롤 공용화

초기 구현은 입력 카드를 별도로 구성해 기존 기능 일부가 누락됐음. 이후 기존 match/[id] 페이지의 점유, 공격 방향, 슈팅, 최근 기록, 점유 타임라인, 경기 흐름 JSX를 MatchControlCards.tsx로 추출하고 두 화면이 함께 사용하도록 변경.

- 영상 화면에서는 카드가 모바일 비율의 단일 열로 쌓이며 우측 컨테이너만 스크롤한다. 기존 페이지의 모바일 탭 동작은 유지한다.
- 점유/이벤트 초기화, 공격 방향 통계, Shot Threat 직접 입력·추정, 골문 도착 좌표, 선수 선택, 상세 로그, 표시 로그 비우기, CSV, 홈/어웨이 색상과 득점 표시가 있는 흐름 그래프를 연결했다.
- 골문 기반 xGOT는 기존 app/xgot.py 계산을 호출한다. 수동 Shot Threat 입력은 기존 매치컨트롤처럼 허용한다.
- 상단에 경기 시작 시각 설정을 항상 표시한다. 현재 영상 시각 가져오기 또는 분:초.밀리초/초 직접 입력 → 저장 → 경기 시작.
- 시작 후 기준을 변경하려면 사용자가 확인한 뒤 기존 점유/이벤트를 초기화한다. 단순 점유 초기화는 이미 관측한 최종 시각을 되돌리지 않는다.
- 로컬 브라우저에서 영상 00:05를 경기 00:00으로 지정·저장하고, 영상 00:12에서 경기 00:07을 확인했다. 피치 선택→위협도 추정→골문 선택→골 저장도 확인했다 (xG .081 / 기존 xGOT 계산 .187).
- API 5개, 시계 4개, 기존 집계 5개와 타입 검사 통과. 운영 배포는 하지 않음.
