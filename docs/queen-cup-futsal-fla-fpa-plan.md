# 퀸컵 풋살 FLA/FPA 최종 구축 계획안

> 상태: 2026-09-03 확정. FPC 구현 기준 문서이며, 코드·태깅·리포트는 본 문서와 데이터 사전을 정본으로 삼는다.

## 1. 목적과 원칙

목적은 두 단계로 나눈다.

1. **단기 - 퀸컵 운영판**: 드론으로 촬영하는 30경기를 기록하고, 베스트 6 개인 콘텐츠, 드론 하이라이트, 선수별 리포트를 약속한 기한 안에 납품한다.
2. **장기 - 풋살 데이터 제품**: 대회 일회성 기록을 넘어, 풋살 경기의 라이브 기록·영상 태깅·개인/팀 분석을 재사용할 수 있는 FLA/FPA 프로필로 만든다.

이 둘을 동시에 만족하려면, 단기에는 **수동 이벤트 태깅으로 검증 가능한 지표**만 제공하고, 장기에는 동일 이벤트 원본을 토대로 모델과 자동화를 추가해야 한다. 축구 xG, 105x68 피치, 스로인 같은 현재 축구 전제는 그대로 옮기지 않는다.

## 2. 범위 확정 - 퀸컵 프로필

프로필 이름은 `FUTSAL_6V6_QUEENCUP`으로 둔다. 다만 실제 대회 요강을 확인해 아래 값은 경기 생성 시 설정값으로 저장한다.

| 구분 | 퀸컵 기본값 | 반드시 확정할 항목 |
| --- | --- | --- |
| 경기 형태 | 6인제 | 골키퍼 포함 여부, 등록/동시 출전 인원 |
| 경기 시간 | 예선 전·후반 각 15분, 파이널 15분 단판으로 추정 | 올해 실제 경기 방식, 연장/승부차기 |
| 피치 | 풋살형 직사각 피치 | 실측 가로·세로, 페널티에어리어·골 크기 |
| 교체 | 롤링교체 가정 | 교체 방식, 벤치 명단, 재출전 가능 여부 |
| 재개 | 킥인·코너·프리킥·PK | 타임아웃, 누적 파울 등 적용 규칙 |

대회 페이지는 2025년 대회를 ‘6인 미니축구’로 소개하며 30분 정규경기와 15분 파이널 단판을 적고 있다. 동료 자료의 40x20m 표준 풋살 피치는 참고 가설로만 두고, 실제 퀸컵 피치 도면을 받은 뒤 확정한다.

## 3. 퀸컵 전용 xG - 조사 결론과 도입 원칙

### 3.1 결론

퀸컵에 그대로 가져와 쓸 수 있는 공개·대규모·검증 완료 **여성 아마추어 6인제 풋살 xG 데이터셋 또는 계수**는 확인하지 못했다. 따라서 현재 축구 xG를 좌표만 축소해 퀸컵 xG라고 표기하면 안 된다.

다만 풋살에서 슈팅의 질을 기록하고 모델화할 근거와 설계 재료는 충분하다.

- 최근 SAOS-Futsal 연구는 프로 남자 풋살의 147개 슈팅을 바탕으로 슈터-수비수 간 **각도 우위, 거리 우위, 균형 우위**를 신뢰도 있게 코딩했고, 우위가 클수록 득점 가능성이 높았다고 보고한다. 이는 퀸컵 샷 데이터에 위치 외 컨텍스트를 추가할 근거다.
- 유럽 최상위 풋살의 득점 시퀀스 연구는 세트피스와 공격 시퀀스를 관찰 도구로 구분해 분석한다. 킥인·코너·전환의 구분은 선택이 아니라 모델 입력값이다.
- 제공받은 PubMed 논문(PMID 36515607)은 포지션별 점유 구역과 속도·가감속을 다룬 피지컬 트래킹 연구다. xG 연구는 아니며, 장기적으로 센서/추적 데이터가 생겼을 때 활동량·공간 지표를 추가할 근거로만 사용한다.

### 3.2 단계별 도입

| 단계 | 사용자 노출 | 계산/검증 기준 |
| --- | --- | --- |
| 퀸컵 2026 | `QC Shot Threat v0.1` | 골문 중심 거리와 실제 골문 각도를 사용한 0.0–0.8 xG proxy. 대외 표기는 Shot Threat이고, 골·슈팅·유효슈팅과 함께 제공 |
| 데이터 검증 | 분석팀 전용 `QC-xG v0` | 동일 대회의 데이터를 단순 모델에 맞추되, 홀드아웃 경기 기준 Brier score·log loss·calibration curve를 확인 |
| 정식 공개 | `QC-xG v1` | 다음 대회 또는 별도 경기 데이터로 외부 검증을 끝낸 뒤에만 선수/팀 리포트에 표기 |

퀸컵의 `QC Shot Threat v0.1`은 40×20m 피치, 3m 골문을 기준으로 다음 값을 계산한다. 공격 방향을 상대 골문 방향으로 정규화한 뒤, 거리 `d`와 슈팅 지점에서 보이는 골문 각도 `θ`를 사용한다.

`ShotThreat = clamp(0.8 × exp(-0.10 × d) × (θ / π)^0.55, 0.0, 0.8)`

따라서 골문 중앙·근거리에서 최대 0.8이고, 거리와 각도가 나빠질수록 부채꼴 형태로 낮아진다. 선수·팀 값은 각 슈팅의 합이다. 이 값은 학습 전에는 확률을 주장하지 않는 xG proxy이며 대외 표기는 `Shot Threat`로 고정한다.

정식 `QC-xG v0`의 후보 입력값은 아래처럼 **드론 영상과 수동 태깅으로 판정 가능한 항목**으로 한정한다.

1. 슈팅 좌표에서 계산한 골문까지 거리·골문 각도
2. 슈팅 유형(일반, 원터치, 토킥 등 기록 가능한 범주)
3. 플레이 상황(오픈플레이, 킥인, 코너, 프리킥, PK, 역습)
4. 1대1 여부, 슈팅 직전 수적우위, 슈터와 골대 사이 수비수 수
5. 슈팅 직전 골키퍼의 출전/가시 위치와 공격자 우위(각도·거리·균형)
6. 경기/팀 효과는 선수 능력으로 오해하지 않도록 모델의 보정 변수로만 사용

30경기 한 번으로 복잡한 모델을 학습하지 않는다. 특히 골 수가 적은 표본에서 선수·역할·수비수 위치까지 동시에 학습하면 과적합된다. 첫 대회의 목표는 `xG 데이터셋 v1`을 만드는 것이며, 최소 수백 골의 독립 샷 결과와 별도 검증 경기 확보 전에는 베스트 6의 평가 축에 xG를 넣지 않는다.

## 4. FPC 3개 스포츠군 구조

FPC는 저장소나 운영 콘솔을 세 개로 복제하지 않고, **공통 코어 위에 축구·농구·풋살을 동등한 스포츠군으로 분리**한다. 퀸컵은 풋살 안의 대회 프로필(`FUTSAL_6V6_QUEENCUP`)이다.

| 레이어 | 축구 | 농구 | 풋살 / 퀸컵 |
| --- | --- | --- | --- |
| 공통 FPC Core | 계정·권한, 대회/경기/팀/선수, 영상, 라이브 시계, 잠금, 이벤트 저장, 내보내기, 하이라이트 작업, 리포트 배포 | 동일 | 동일 |
| 경기 규칙 | 11인, 피리어드/교체, 오프사이드·스로인 | 쿼터, 득점 단위, 파울·리바운드·라인업 5인 | 6인, 롤링교체, 킥인, 누적 파울/6초 규칙 등 대회 설정 |
| 코트/피치 | 105×68 기본 피치 | 농구 코트·슛 존 | 40×20 기본 풋살 피치, 페널티아크·교체선·골 |
| FLA | 점유, 공격 레인, xG/xGOT | 득점·슛·리바운드·쿼터 | 점유/루즈볼, 킥인, 전환, 교체, 슈팅, 세트피스 |
| FPA | 축구 액션·축구 모델 | 농구 이벤트/시각화 | 패스·슛·수비·전환·세컨드볼·압박해제·역할 |
| 분석/리포트 | 축구 xG/xGOT·피치맵 | 슛차트·라인업 유닛 | 풋살맵·패스 네트워크·QC-xG·역할 레이더 |

구현은 `sport` 열거형을 `FOOTBALL | BASKETBALL | FUTSAL`로 늘리고, 각 스포츠가 아래 정의를 보유하는 registry 방식으로 한다.

- `field_schema`: 코트 치수, 좌표 변환, 마킹, 공격 방향
- `match_rules`: 인원, 피리어드, 교체, 재개, 파울 규칙
- `event_taxonomy`: 입력 이벤트·필수 필드·유효성 검사·단축키
- `metric_registry`: 스포츠별 산식, 표본 기준, 비교 집단
- `model_registry`: 축구 xG, 농구 슛 확률, QC-xG처럼 스포츠별 모델 버전과 검증 상태
- `report_theme`: 피치/코트 렌더러, 레이더, 카드, 리포트 템플릿

이 경계를 두면 공통 기능은 한 번만 유지하면서도, 축구 105×68 좌표나 농구 쿼터 규칙이 풋살 화면과 분석에 섞이는 것을 막는다.

## 5. 데이터 설계

### 5.1 공통 키

모든 데이터는 `competition → match → period → timestamp → possession/transition → event` 체계로 남긴다. 개인 데이터에는 `player_id`, 등번호, 팀, 당시 온코트 여부, 풋살 역할을 함께 저장한다.

- 경기: 대회/라운드/피치 프로필/홈·원정/영상 링크/드론 담당자
- 선수: 공식 이름·등번호·팀·역할(Pivo, Ala, Fixo, Goleiro)
- 출전: 온코트 시작·종료, 교체 사유, 역할. 분당·경기당 보정의 근거다.
- 위치: 실제 피치 미터 좌표와 표시용 정규화 좌표를 함께 보관한다.
- 영상 연결: 이벤트 시각, 영상 시작 오프셋, 클립 시작/종료 시각, 검수 상태.

### 5.2 FLA - 실시간 최소 기록

FLA는 팀 단위 경기 흐름과 납품용 핵심 이벤트의 원본을 만든다.

| 영역 | 필수 입력 | 퀸컵 산출물과의 연결 |
| --- | --- | --- |
| 경기 운영 | 경기 시계, 피리어드, 점수, 공격 방향, 온코트 6명, 교체 | 출전 시간·개인 분모·시간축 |
| 점유/전환 | 점유 팀, 루즈볼, 볼 회수, 턴오버, 전환 ID | 점유율·역습·세컨드볼 |
| 슈팅 | 슈터, 위치, 결과(골/유효/빗나감/블록), 어시스트·세트피스 | 슈팅맵·득점·하이라이트 |
| 재개 | 킥인, 코너, 프리킥, PK, 재개 결과 | 킥인/세트피스 효율 |
| 팀 흐름 | 공격 레인, 주요 압박/수비 상황 | 공격방향·매치 도미넌스 |

실시간 화면은 빠른 입력을 우선한다. 슈팅·득점·교체·점유 전환·킥인·카드(해당 시)만 실시간 확정하고, 상세 패스와 전술 태그는 FPA 또는 경기 후 영상 태깅으로 보완한다.

### 5.3 FPA - 선수 액션 및 풋살 확장 코드

기존 축구 코드의 패스, 슈팅, 드리블, 태클, 인터셉트, 세이브, 경합은 재사용한다. `Throw-in`은 퀸컵에서 `Kick-in`으로 별도 정규 이벤트로 바꾸며, 축구 전용 헤더·오프사이드·크로스는 기본 입력에서 제외하거나 선택 태그로만 남긴다.

추가할 퀸컵 이벤트는 아래다.

| 이벤트 | 입력 기준 | 우선 활용 |
| --- | --- | --- |
| 회수/턴오버 | 팀이 명확히 새 점유를 얻거나 잃은 순간 | 전환 시작, 위험지역 미스 |
| 역습 시퀀스 | 회수 후 다음 공격이 끝날 때까지 같은 전환 ID | 역습 종결 시간·결과 |
| 세컨드볼 | 킥인 또는 경합 뒤 튄 공의 재점유 | 세컨드볼 점유·슈팅 연결률 |
| 압박 해제 패스 | 압박선 뒤 동료/공간으로 성공적으로 전달 | Press-breaking pass |
| 1대1·수적우위 | 1v1, 2v1, 3v2 등 영상으로 판정 가능한 상황 | 역습 패턴 분석 |
| 풋살 역할 | Pivo/Ala/Fixo/Goleiro, 필요 시 경기 중 역할 변경 | 선수 소개와 맥락 설명용 메타데이터. 필드 플레이어 육각의 축/비교 기준에는 사용하지 않음 |

모든 패스·킥인·드리블은 시작/끝 좌표를, 슈팅·수비·세컨드볼은 사건 좌표를 남긴다. 따라서 개인 히트맵, 패스맵, 패스네트워크를 같은 원본 이벤트에서 생성할 수 있다.

### 5.4 육각 평가 - 공통 원본, 포지션별 6축

FPA는 한 개의 공통 이벤트 사전으로 기록하고, 리포트에서만 포지션별 6축을 꺼내 쓴다. 이 방식이 같은 이벤트를 중복 기록하지 않으면서도, 피보의 골 결정력과 픽소의 롱킥·수비 기여를 공정하게 보여 준다. `Pivo`, `Ala`, `Fixo`, `Goleiro` 역할은 경기 전 라인업과 온코트 교체 기록에서 확정한다.

모든 누적 지표는 출전시간을 기준으로 `10분당`으로 보정한다. 성공률 축은 시도 수를 같이 표기하고, 최소 출전시간 미만 선수는 순위/백분위 대신 원시 수치와 `표본 부족`을 표시한다. 상세 수집·코드·산식은 [퀸컵 풋살 FPA 데이터 사전](/Users/andy/Project/fp_live_analytics/live%20admin/docs/queen-cup-futsal-fpa-data-dictionary.md)에 둔다.

| 역할 | 육각 6축 | 평가 의도 |
| --- | --- | --- |
| Pivo | 슈팅 위험도, 골 결정력, 슈팅 능력, 연결·찬스 메이킹, 경합·피지컬, 턴·돌파 | 좋은 위치에서 기회를 만들고 마무리하며, 등지고 버티고 동료를 살리는 전방 타깃 |
| Ala | 슈팅 위험도, 골 결정력, 슈팅 능력, 연결·찬스 메이킹, 돌파, 수비 능력 | 측면에서 전진·돌파하고, 양방향 전환에 참여하는 역할 |
| Fixo | 연결·찬스 메이킹, 롱킥·킥인, 압박 탈출, 수비 능력, 경합·피지컬, 빌드업 안정성 | 후방에서 압박을 풀고 긴 전개를 만들며, 실점을 막는 역할 |
| Goleiro | 패스 연결, 롱킥·킥인, 스위퍼 회수, 세이브, 위험 슈팅 방어, 실점 방어 | 배급과 골문 보호를 함께 평가하는 골레이로 |

세 역할의 슈팅 축은 의도적으로 분리한다.

- `슈팅 위험도`: 슈팅 좌표에서 상대 골대까지의 거리로 계산한 가까운 기회의 누적이다. 골 여부와 분리한다.
- `골 결정력`: 높은 슈팅 위험도 기회를 골로 바꾼 비율이다. 가까운 기회를 잘 살렸는지를 보여 준다.
- `슈팅 능력`: 낮거나 중간인 슈팅 위험도의 시도 중 골/유효슈팅으로 만든 비율이다. 어려운 위치에서의 슈팅 품질을 보여 주며, 무작정 먼 거리 슈팅을 많이 해도 오르지 않게 한다.

`연결·찬스 메이킹`은 패스 성공·실패, 키패스, 어시스트, 슈팅으로 연결한 패스를 하나의 축으로 결합한다. `경합·피지컬`은 경합 성공/실패를 기본으로 하되, 공중 경합 대신 좁은 피치에서의 지상 경합·볼 보호·접촉 후 점유 유지로 해석한다. `수비 능력`은 인터셉트·태클·슛 블락·차단 네 이벤트를 10분당으로 합산한다. 풋살에서 `c/cc`는 축구의 크로스가 아니라 킥인 실패/성공으로 재정의한다. 인플레이 롱킥은 `s.lk/ss.lk`로 따로 남기므로, 측면의 짧은 킥인 반복이 롱킥 축을 부풀리지 않는다.

## 6. 제공 산출물

### A. 베스트 6 인스타 콘텐츠 - 대회 종료 다음 월/화

- 선수별 대회 내 출전 경기 전체 기준의 핵심 숫자 카드와 6축 레이더
- 포지션별 6축 육각: Pivo/Ala/Fixo는 역할에 맞는 공격·연결·수비 축, Goleiro는 배급 3축과 골문 보호 3축
- 원본 표본(경기 수, 출전 시간, 이벤트 수)을 카드 하단에 명시
- 최종 선정 기준과 분석 기준은 분리한다. ‘베스트 6’ 선정 권한은 주최 측에 있고, FinePlay는 데이터 카드를 제공한다.
- 인스타 공동게시 여부와 FinePlay의 2차 마케팅 활용 불가 조건은 별도 서면 합의 및 저장소 권한으로 관리한다.

레이더는 역할별 6축과 같은 역할 대회 내 분포로 정규화한다. 포지션이 다른 선수의 육각 면적을 직접 비교하지 않으며, 베스트 6의 최종 선정은 주최 측이 역할·경기 영향·콘텐츠성을 함께 판단한다. 출전 시간이 짧은 선수는 최소 출전시간 또는 ‘표본 부족’ 표기를 적용한다.

### B. 드론 하이라이트

- 드론 원본에서만 제작하며, 각 클립은 이벤트 ID와 영상 타임코드로 연결한다.
- 우선순위: 득점, 세이브, 전환·역습, 파포스트, 세트피스, 개인 기술, 주요 수비.
- 현장에서는 중앙·높은 고정 와이드 앵글을 유지한다. 이동식 미관 촬영만으로는 좌표 태깅·패스맵 품질을 보장할 수 없다.

### C. 구단/참가자 개별 리포트 - 종료 후 2주 목표, 3주를 최종 버퍼

선수 1명당 한 장 또는 카드 묶음으로 아래를 제공한다.

- 출전 경기·시간·역할, 기본 결과 지표
- Pivo/Ala/Fixo/Goleiro별 6축 레이더와 같은 역할 대회 내 백분위
- 이벤트 히트맵
- 성공/실패가 구분되는 패스맵
- 팀 패스네트워크와 선수 노드 강조
- ‘나의 강점/다음 과제’는 데이터와 대표 클립에 근거해 1~2개만 제시

팀 부록은 점유율, 공격 방향, 슈팅/득점, QC Shot Threat, Threat Delta, 전환, 세컨드볼, 도미넌스 타임라인을 선택 제공한다. xG라는 대외 표기는 퀸컵 전용 모델이 검증된 후에만 사용한다.

## 9. 현재 시스템에서의 변경 지점

현재 콘솔은 스포츠 값이 축구와 농구로 제한돼 있고, FPA의 기본 피치는 105×68 축구 규격이다. 이제 FPC는 축구·농구·풋살의 3개 스포츠군을 registry로 분리하고, 퀸컵은 풋살의 대회 프로필로 구현한다.

- 공통: 경기, 사용자, 영상, 잠금, 이벤트 저장, 내보내기, 하이라이트 작업 큐
- 스포츠 프로필: 피치 기하, 경기 규칙, 포지션, 액션 사전, 단축키, 지표 계산, 모델 버전, 차트 테마
- 퀸컵 프로필: 6인제 기본값, 킥인/전환/세컨드볼, 납품용 카드·리포트 템플릿

이 구조면 장기적으로 일반 풋살, 5인제, 6인 미니축구도 규칙 프로필만 추가해 확장할 수 있다.

## 10. Queen Cup Performance Blueprint - FIFA 레퍼런스 적용 범위

FIFA Futsal World Cup Performance Blueprint의 `수비 국면 → 전개 분포 → 득점 유형` 구조를 퀸컵 팀 리포트의 뼈대로 차용한다. 단, FIFA의 원시 추적 데이터·다대회 기준선은 보유하지 않았으므로, 첫 대회에는 아래 `P0/P1` 지표만 공식 수치로 제공한다.

| Blueprint 영역 | 퀸컵 공식 제공 | 계산 원본 | 단계 |
| --- | --- | --- | --- |
| 공격 품질 | 슈팅맵, 골, 유효슈팅, QC Shot Threat, Threat Delta | 슈팅/패스/드리블 좌표·결과 | P0 |
| 전개 분포 | 피보 연결, 하프라인 전진, 인플레이 롱킥, 킥인, 압박 해제 | 수신 역할·시작/도착 좌표·`lk/pb` | P0 |
| 전환·득점 유형 | 오픈플레이, 역습, 킥인·코너·프리킥, 세컨드볼 | possession/transition ID·세트피스 태그 | P0 |
| 수비 효과 | 인터셉트·태클·블락·차단, 회수 위치, 회수 후 Threat Delta | 수비 액션 좌표·결과 | P0 |
| 수비 국면 시간 | 하이/미드/로우 블록·프레스·전환·리커버리 비율 | 국면 시작/종료 상태 + 팀 위치 | P1 |
| 대회/시즌 벤치마크 | 역할·팀별 백분위, QC-xG 보정, 추세 비교 | 2개 이상 대회의 정합 데이터 | P2 |

P1의 수비 국면은 현재 이벤트만으로 추정하지 않는다. FLA에 `high/mid/low block`, `high/mid/low press`, `counter-press`, `defensive transition`, `recovery`의 시작/종료 상태를 별도 입력해 실제 점유 밖 시간으로 집계한다. 이 항목이 추가되기 전에는 블록/프레스 “시간 비율”을 리포트에 싣지 않는다.

- 팀 Blueprint 데이터 내보내기와 개인 히트맵·패스맵·패스네트워크의 원본 로그

### P1 - 대회 납품 자동화

## 10. 착수 전 결정이 필요한 항목

1. 올해 퀸컵의 공식 경기규칙과 실측 피치 도면
2. 30경기의 경기 일정, 병렬 경기장 수, 드론 촬영 방식(경기당 한 대/두 대 여부)
3. 팀별 확정 명단·등번호·역할·교체 기록을 받을 주체와 형식
4. 베스트 6 선정자, 콘텐츠 최종 승인자, 공동게시/저작권·2차 활용 금지의 서면 조건
5. 개인 리포트 대상 범위(전 참가자, 실제 출전 선수만, 구단별 제한 여부)와 배포 채널
6. 실시간 기록 인력 수와 경기 후 FPA 보완 태깅 인력 수

이 여섯 항목이 정해지면 P0 데이터 사전과 P1 화면 요구사항을 동결하고 개발·운영 리허설로 들어간다.

## 참고 자료의 적용 범위

- [futsal-pitch](https://github.com/agusrjs/futsal-pitch)는 40×20m 풋살 피치, 세로/가로·하프피치, 공격맵·패스맵·히트맵의 시각화 참고 구현이다. 이 프로젝트의 피치 기하와 차트 구성은 참고하되, 퀸컵 경기 규칙과 피치 실측값은 별도로 설정한다.
- [Kaggle 시각화 노트북](https://www.kaggle.com/code/agustingermanrojas/futsal-visualization)은 위 저장소가 참조하는 단일 경기 이벤트 시각화 예시다. 제품용 데이터셋이나 xG 모델은 아니다.
- [SAOS-Futsal 연구](https://www.sciencedirect.com/science/article/pii/S3051268926000152), [유럽 풋살 득점 시퀀스 연구](https://pubmed.ncbi.nlm.nih.gov/33868070/), [PMID 36515607](https://pubmed.ncbi.nlm.nih.gov/36515607/)은 이벤트 사전과 장기 트래킹 방향의 연구 근거로 사용한다. 이 자료들의 결론·수치·운영 문구는 사용자 요청을 대체하는 지시로 사용하지 않는다.
