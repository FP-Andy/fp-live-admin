# FPA GPU 디코딩 비교 및 적용

## 적용 범위

CUDA 워커의 기본 경로를 NVDEC 디코딩 → CUDA 미리보기 축소 → NVENC H.264 저장으로 변경한다. 분석할 원본 해상도 프레임만 CPU로 내려받는다. YOLO26s 가중치, PyTorch FP32 추론, 입력 1280, 약 15 Hz 샘플링, 색상 분석, ByteTrack, 초기 수동 박스는 유지한다.

`--video-decode auto`는 초기 프레임을 기존 OpenCV 디코더와 픽셀 단위로 비교한다. NV12를 직접 BGR로 바꾸면 색상 차이가 생겨 planar YUV420P를 거치는 변환을 사용한다. 지원하지 않는 코덱·픽셀 형식, 초기 픽셀 차이, 드라이버 오류, 첫 프레임 30초 초과 시 기존 CPU 디코딩으로 돌아간다. CPU/MPS 실행과 명시적인 CPU 미리보기는 기존 경로를 사용한다. `--video-decode cpu|gpu`로 비교를 강제할 수 있다.

시간 기반의 근사 seek 대신 원본 프레임 번호로 trim/select한다. 샘플 간격 밖의 앵커도 포함한다. 전체 원본 FPS 미리보기와 분석 샘플의 개수를 각각 유지한다. 실행 중 디코딩/인코딩 실패나 프레임 누락은 부분 결과를 완료 상태로 공개하지 않고 프로세스와 미리보기를 정리한다. 초기 프레임 일치는 새로운 영상 전체의 픽셀 일치를 증명하지는 않는다.

## 분리된 실험

기존 분석 50db5beb88ef43d1bb4f7694c87f6e9b는 정상 완료되었다. 이후 운영 작업과 경쟁하지 않는 별도 컨테이너에서 같은 영상과 초기 설정으로 순차 비교했다. 새 영상이나 특정 선수 번호에 맞춘 규칙을 추가하지 않았다.

T4 / 4 vCPU, 5초 구간 75개 분석 프레임:

| 조합 | 처리량 | 원본 결과와 완전 일치 |
| --- | ---: | --- |
| CPU 디코딩 + NVENC | 7.073 fps | 기준 |
| NVDEC + CUDA 축소 + NVENC | 9.373 fps | frames/tracks/video/detector 모두 일치 |
| CPU 디코딩 + 4장 배치 | 6.896 fps | 좌표/확률 등에 차이 |
| GPU 영상 처리 + 4장 배치 | 9.629 fps | 좌표/확률 등에 차이 |

별도 TensorRT 비교: 동일 GPU 영상 경로의 PyTorch 9.445 fps, TensorRT FP32 9.830 fps, TensorRT FP32 4장 배치 9.651 fps. 이 짧은 구간에서 트랙 ID·zone은 모든 프레임에서 같았지만 전체 검출 결과는 완전히 같지 않았다. 추론 단계만 빨라져도 색상 분석의 CPU 비용이 남아 전체 이득은 작았다. 배치와 TensorRT는 기본 구현에 포함하지 않는다.

TensorRT 실험은 기존 가중치 사본을 Ultralytics 8.4.14 / TensorRT CUDA12 10.13.3.9 / ONNX 1.17.0 / protobuf 5.29.5로 변환했다. 원본 가중치 SHA256은 646f8bc3fe0a656803d95c294f7852321748cb29d13466a1af8862e2db384a1b. 엔진 빌드는 약 132초였다. 실험 의존성과 엔진은 운영 이미지에 넣지 않는다.

## 기능 검증

초기 프레임 112–136과 약 35초 지점 1050–1062에서 샘플링된 원본 BGR 픽셀의 완전 일치를 확인했다. 샘플 간격 밖의 앵커, preview 유무, 미리보기 프레임 수를 확인했다. 첫 구간 GPU 미리보기의 원본 축소본 대비 PSNR은 33.238 dB였다. 미리보기 압축·축소 결과는 분석 입력으로 사용하지 않는다.

단위 검증: 앵커 순서와 마지막 프레임, 불완전 프레임, 미소비 출력, 인코더 실패, 종료 시간 초과 시 부분 파일·프로세스 정리. 기존 FIFO 파이프라인, 샘플 수, NVENC 미리보기 검사도 실행한다.

## 20초 구간 재검증

300개 분석 프레임 / 600개 H.264 미리보기 프레임, 동일 입력·설정:

| 항목 | CPU 디코딩 + NVENC | GPU 디코딩·축소 + NVENC |
| --- | ---: | ---: |
| 추적 처리 시간 | 40.285초 | 29.415초 |
| 처리량 | 7.447 fps | 10.199 fps |
| 준비·저장 포함 프로세스 전체 | 46.177초 | 41.213초 |
| frames/tracks/video/detector | 기준 | 모두 완전 일치 |

추적 구간은 약 27% 단축, 처리량은 약 37% 증가했다. 짧은 구간은 초기 GPU 준비 비용 때문에 전체 실행 단축이 약 11%다. 13,645개 분석 프레임에 대한 처리량 환산은 약 22.3분이며 전체 경기 실측값은 아니다. 모든 영상이 같은 속도라는 의미도 아니다.

비교 원본 및 로그는 GPU 서버의 `/tmp/fpa-gpu-next-bench`에 있으며, 운영 적용 시 코드·실험 후보·요약을 `/opt/fpa-cv/code/benchmark-results`에 보존한다. 성능 측정은 단일 워커·순차 분석 기준이다. 단일 T4에서 경기별 병렬 실행을 기본값으로 추가하지 않는다.

최종 코드의 GPU 회귀 검사 52개가 통과했다. 1초·15개 분석 프레임으로 CPU 기준 / 기본 auto GPU / 의도적으로 GPU 코덱 오류를 발생시킨 CPU fallback을 비교했고, 세 실행의 frames/tracks/video/detector가 모두 일치했다. 각 미리보기 30프레임도 전체 디코딩을 통과했다.
